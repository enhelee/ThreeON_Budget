## 0. 구성 한눈에

```
                 https://<주소>/
 ┌──────────────── Caddy (:8080, 리버스 프록시·정적) ────────────────┐
 │  /            소개·문서 사이트 (docs/index.html, 정적)              │
 │  /app/ /api/  budget_app  FastAPI :8010  ── 공용비밀번호 로그인+작업자 이름+감사로그
 │  /forecast    forecast_app Streamlit :8501 ── Caddy basic_auth(같은 공용비밀번호)
 └────────────────────────────┬───────────────────────────────────────┘
                              │ DATABASE_URL
                    PostgreSQL(Supabase 무료 / 사내 PG)  ← 비우면 SQLite(볼륨)
```
세 프로세스를 `supervisord`가 한 컨테이너에서 띄운다. 무료 PaaS가 **컨테이너 1개·포트 1개**만 열어주기 때문이며, 사내 서버에서도 같은 이미지를 그대로 쓴다(`docker-compose.yml`).

| 파일 | 역할 |
|---|---|
| `deploy/Dockerfile` | python:3.12-slim + Caddy + 두 앱 + 사이트. 실데이터·.env·산출물은 `.dockerignore`로 절대 포함 안 됨 |
| `deploy/Caddyfile` | 경로 라우팅, 보안 헤더, `/forecast` basic_auth |
| `deploy/supervisord.conf` | uvicorn·streamlit(`--server.baseUrlPath=forecast`, CWD=/data/forecast)·caddy |
| `deploy/entrypoint.sh` | 볼륨 폴더 생성, `APP_PASSWORD` → Caddy bcrypt 해시, 경고 출력 |
| `deploy/render.yaml` | Render Blueprint(무료 웹서비스) |
| `deploy/docker-compose.yml` | 사내 서버: 볼륨 + (선택) PostgreSQL 컨테이너 |
| `deploy/.env.example` | 비밀 설정 키 목록(값 없음). 복사해 `.env` |
| `deploy/requirements.txt` | 두 앱 통합 의존성(streamlit 1.59·pandas 2.2.3·psycopg 3) |

환경변수(비밀은 `.env`/PaaS 대시보드에만): `APP_PASSWORD` `SECRET_KEY` `DATABASE_URL` `SESSION_HOURS` `COOKIE_SECURE` `BASIC_USER`. 자세한 의미는 `.env.example`.

## 1. 지금 단계 — 무료 공개 배포 (Render + Supabase + GitHub Pages)

### 1.1 플랫폼 검토 결과 (사용자 요청: Render / Vercel / Supabase)

| 후보 | 판정 | 근거 |
|---|---|---|
| **Render Web Service (Docker, Free)** | **앱 2종 배포 — 채택** | Docker 이미지 그대로, HTTPS 자동, GitHub 연동 자동 배포. 제약: 15분 미사용 시 슬립(첫 접속 30~60초), **디스크 비영속**(재배포 시 파일 초기화) → DB는 외부(Supabase) |
| **Supabase (PostgreSQL, Free)** | **DB — 채택** | 500MB·영속·백업 UI·SSL. 우리 데이터(23·25년 ERP 2.4만 행 + 매칭 이력 정리본 ≈ 20~30MB)에 충분. 7일 미접속 시 프로젝트 일시정지(대시보드에서 재시작). 나중에 Supabase Auth로 **개인 계정** 확장 가능 |
| **Vercel** | **소개 사이트만 가능, 앱은 부적합** | 서버리스 함수(기본 10초·최대 60초 제한), 영속 프로세스·WebSocket 없음 → Streamlit 구동 불가, budget_app 분석(16~19초)·파일 산출물도 제한에 걸림. 정적 `docs/`만 배포 가능 |
| **GitHub Pages** | **소개 사이트 — 채택(기본)** | 무료·영구·저장소에서 바로. 공개 저장소면 사이트도 공개 |
| Hugging Face Spaces (Docker) | 대안 | 슬립 없음(48시간 미사용 시 정지), 포트 7860 단일 → 같은 이미지에 `PORT=7860`으로 가능. 디스크 비영속 동일 |
| Streamlit Community Cloud | 비채택 | v2만 올릴 수 있어 주소가 둘로 나뉘고 budget_app 연계 불가 |

### 1.2 실데이터를 공개 클라우드에 두는 문제 — 반드시 읽을 것
사용자 결정은 "가상 데이터가 아닌 **실데이터**를 팀원만 접근해 업로드·수정". 기술적으로는 아래 §2 보안 구성으로 팀 외 접근을 차단하지만, **회사 실적·예산 데이터를 외부 클라우드(Render·Supabase)에 저장하는 것은 사내 정보보호 규정 확인이 먼저**다. 이 문서는 "최종은 사내 서버"를 전제로, 무료 배포 기간을 **팀 검토용 임시 운영**으로 본다. 권장 원칙:
- 공개 배포 기간에는 **필요한 연도만** 업로드하고, 검토가 끝나면 Supabase 테이블을 비우거나 프로젝트를 삭제한다.
- 팀 공용 비밀번호는 12자 이상, 메신저 비밀 메모로만 전달, 팀 변동 시 즉시 교체(Render 환경변수 수정 → 자동 재배포).
- Supabase 대시보드 로그인에 2단계 인증을 켠다(DB 자체 접근 권한이므로 가장 중요).

### 1.3 배포 절차
**A. GitHub 업로드**
1. `2026-09-09_팀공유(취합본)_v0/` 내용을 저장소 `enhelee/ThreeON_Budget`의 새 폴더 `2026-09-09_팀공유(취합본)_v0/`로 올린다(패키지 `.gitignore`가 실데이터를 걸러준다 — 업로드 전 `git status`로 `.env`·`*.db`·`*.csv`가 없는지 확인).
2. Render는 저장소 루트의 `render.yaml`을 찾으므로, 저장소 **루트**에 `render.yaml`을 두고 `dockerContext: ./2026-09-09_팀공유(취합본)_v0` · `dockerfilePath: ./2026-09-09_팀공유(취합본)_v0/deploy/Dockerfile`로 경로만 고친다(패키지 안 `deploy/render.yaml`은 패키지 자체를 루트로 올릴 때의 값).

**B. Supabase**
1. supabase.com → New project(리전 `Northeast Asia (Seoul)`), DB 비밀번호 생성·보관.
2. Project Settings → Database → Connection string → **Transaction pooler(포트 6543)** 문자열 복사, 끝에 `?sslmode=require`.
3. 로컬에서 먼저 검증: `budget_app/.env`에 `DATABASE_URL=…` 넣고 `py scripts/db_check.py` → 표 18개 생성·조회 OK 확인. 기존 SQLite 데이터를 옮길 땐 `py scripts/db_check.py --migrate`(로컬 `data/budget.db` → PG 전체 복사).
   - ✅ PostgreSQL 경로는 **로컬 PostgreSQL 16.4 실서버로 검증 완료**(2026-09-09): 스키마 18표 생성, 실데이터 전체 이전(erp_row 43,840행 등 13표, 16초), 인증·레지스트리 API 테스트 4건, 전체 API 워크로드(overview·status·branches·branch-detail·stats·export-team·analyze·manual-biz·lock 423·learn·audit) 통과. **내보내기 합계가 SQLite와 원 단위까지 동일**(손익 98,554,800,525 · 자본 49,709,177,979). 이 과정에서 PG `REAL`(float4) 정밀도 손실(−50원/+144원)을 발견해 `REAL→DOUBLE PRECISION` 번역을 추가했다 — Supabase에서도 `db_check.py` 첫 실행으로 표를 만들면 자동 적용된다. Supabase는 네트워크·SSL만 다르므로 `db_check.py` 통과 여부만 확인하면 된다.
   - 이전(`--migrate`)은 **대상 표를 비우고 전체 교체**한다(부분 병합 아님). 이력을 줄이려면 먼저 `py scripts/db_정리.py`.

**C. Render**
1. render.com → New → Blueprint → 저장소 선택 → `render.yaml` 인식 → Apply.
2. Environment에 `APP_PASSWORD`(팀 공용), `DATABASE_URL`(Supabase) 입력. `SECRET_KEY`는 자동 생성.
3. 첫 빌드 5~8분(Caddy 다운로드·pip). 완료 후 `https://threeon-budget.onrender.com/healthz` → `{"ok":true,"auth":true,"db":"postgresql"}` 확인.
4. 접속: `/`(소개) · `/app/`(budget_app 로그인: 작업자 이름+비밀번호) · `/forecast`(브라우저 기본인증: 사용자 `team`, 비밀번호=APP_PASSWORD).

**D. GitHub Pages(소개 사이트)**
- 저장소 Settings → Pages → Source: Deploy from a branch → 폴더를 `/docs`로 지정하려면 패키지의 `docs/`가 저장소 루트 `docs/`여야 한다. 하위 폴더에 올리는 경우엔 `docs/index.html`을 저장소 루트 `docs/`로 복사하거나, Vercel(정적, Root Directory=`2026-09-09_팀공유(취합본)_v0/docs`)을 쓴다.

**E. forecast_app(v2) 데이터 주의**
- v2는 CSV 파일 저장이라 Render 무료 디스크에서는 **재배포 시 초기화**된다. 검토 기간엔 budget_app의 결과 JSON을 다시 올려 연결(1~2분)하는 것으로 충분하며, 영속이 필요하면 Render Persistent Disk(유료, `/data/forecast` 마운트) 또는 사내 서버(§3 볼륨)를 쓴다.
- 모델·학습데이터는 budget_app의 **DB 레지스트리**에 있으므로 재배포에도 보존된다. v2가 읽을 파일은 `py scripts/v2_model_sync.py --pull`로 내려받는다([학습데이터_모델_관리.md](학습데이터_모델_관리.md)).

### 1.4 운영 점검 항목(무료 배포)
- 슬립 해제 지연을 팀에 공지(첫 접속 30~60초).
- 월 750시간 무료 한도(단일 서비스면 상시 가동 가능).
- Supabase 7일 미접속 정지 → 주 1회 접속 또는 재시작.
- 비밀번호 교체 = Render 환경변수 수정 → 재배포(1~2분). 세션은 SECRET_KEY가 유지되면 남는다(강제 로그아웃은 SECRET_KEY 재생성).

## 2. 보안 구성 요약 (상세: [보안설계.md](보안설계.md))
- **2중 게이트**: `/forecast`는 Caddy basic_auth(bcrypt 해시는 기동 시 계산), `/app·/api`는 FastAPI 로그인(HMAC 서명 쿠키, HttpOnly·SameSite=Lax·Secure).
- **수정 이력**: 로그인 때 받은 **작업자 이름**이 세션에 들어가고 모든 변경 API가 `audit_log`(시각·작업자·경로·상태·요약)에 기록된다. 설정 탭 「변경 이력」에서 조회.
- **비밀은 Git 밖**: `.env`(gitignore)·Render 환경변수·Supabase 대시보드. 코드·문서·이미지에 비밀번호·연결문자열 없음(`.dockerignore`가 `.env`·DB·CSV 차단).
- **실데이터는 Git 밖**: 패키지 `.gitignore` + v2 폴더 `.gitignore`가 `*.db`·`data_*.csv`·모델 파일 제외.

## 3. 최종 단계 — 사내 서버(분리망) 배포

목표 구성: 사내 리눅스 서버(또는 Windows + Docker Desktop) 1대, 사내망에서만 접속, 데이터는 서버 볼륨(SQLite) 또는 사내 PostgreSQL.

### 3.1 Docker가 있는 경우(권장)
```bash
cd 2026-09-09_팀공유(취합본)_v0
cp deploy/.env.example .env      # APP_PASSWORD, SECRET_KEY 채움. COOKIE_SECURE=0(사내 http) 
docker compose -f deploy/docker-compose.yml up -d --build           # SQLite(볼륨 budget_data)
docker compose -f deploy/docker-compose.yml --profile pg up -d --build   # PostgreSQL 컨테이너 포함
```
- 접속 `http://<서버IP>:8080/`. 사내 HTTPS가 필요하면 앞에 사내 프록시(nginx/IIS)를 두고 `COOKIE_SECURE=1`.
- 백업: SQLite 모드 = 볼륨 `budget_data`의 `budget.db` 1파일(+`forecast_data`). PG 모드 = `pg_dump`.
- **분리망(인터넷 없음)**: 인터넷 PC에서 `docker build -t threeon-budget .` 후 `docker save threeon-budget | gzip > threeon-budget.tar.gz` → 반입 → `docker load`. 이미지 안에 pip 패키지·Caddy가 모두 들어 있어 서버에서 인터넷이 필요 없다.

### 3.2 Docker가 없는 경우(Python만)
- 인터넷 PC: `py -m pip download -r deploy/requirements.txt -d pkgs` → `pkgs/` 반입 → `py -m pip install --no-index --find-links pkgs -r deploy/requirements.txt`.
- budget_app: `budget_app/.env` 작성 → `py -m uvicorn server:app --host 0.0.0.0 --port 8010`(팀원은 `http://서버IP:8010`).
- forecast_app: `cd forecast_app && py -m streamlit run app.py --server.address 0.0.0.0` (`http://서버IP:8501`). 이 경로엔 Caddy가 없어 v2 앱에 비밀번호 게이트가 없다 → 사내망 신뢰 범위에서만.
- Windows 서비스 등록은 `NSSM` 또는 작업 스케줄러(로그온 시 실행) 사용.

### 3.3 사내 이관 체크리스트
- [ ] Supabase → 사내 PG 이전: `pg_dump`(Supabase) → `psql`(사내) 또는 로컬 SQLite로 내려 `db_check.py --migrate`.
- [ ] `.env` 재작성(사내 주소·새 비밀번호), Render 서비스·Supabase 프로젝트 **삭제**(외부 실데이터 잔존 제거).
- [ ] 소개 사이트는 사내 서버 `/`에서 그대로 서비스(GitHub Pages는 공개 정보만 남기거나 내림).
- [ ] 개인 계정 전환 검토: Supabase Auth 또는 FastAPI 사용자 표(`audit_log.operator`가 이미 사람 단위라 전환 비용 낮음).

## 4. 로컬 개발·검증
- budget_app: `cd budget_app && py -m pytest -q`(2026-09-09 기준 통과 수는 CHANGELOG 참조). `.env`의 `APP_PASSWORD`를 비우면 로그인 없이 개발.
- forecast_app: `cd forecast_app && py -m pytest tests/ -q`(183 passed, Python 3.14·pandas 3.0에서도 통과).
- 통합 이미지 빌드 검증(Docker 있는 PC): `docker build -f deploy/Dockerfile -t threeon-budget . && docker run --rm -p 8080:8080 -e APP_PASSWORD=test threeon-budget` → `/healthz`, `/app/`, `/forecast`.
  이 PC에는 Docker가 없어 **이미지 빌드 자체는 미검증**이다. 대신 컨테이너 안과 같은 구성을 Windows에서 직접 띄워 검증했다(2026-09-09): Caddy 2.8.4(`caddy validate` 통과) :8080 → uvicorn :8010 · Streamlit :8501(`--server.baseUrlPath=forecast`). 결과: `/` 소개 사이트 200, `/healthz` 200, `/app/` 200(로그인 오버레이 → 작업자 배지 → `/api/export-team` 200), `/forecast` 인증 없이 401 · `team`+비밀번호로 200. 즉 Caddyfile·라우팅·기본인증·SPA 절대경로(`/api`)·Streamlit 서브패스는 실증됐고, 남은 미검증은 Dockerfile의 빌드 단계(apt·Caddy 다운로드·pip)뿐이다 — Render 첫 빌드 로그로 확인.
