예산 실적 자동분석 — 알고리즘 명세

유저플로우의 모든 자동 판정은 결정적 규칙기반(rule-based)이며, 유일한 근사 요소는 문자열 유사도(rapidfuzz WRatio)입니다. 같은 입력이면 항상 같은 결과가 나오고(재현 가능), 모든 판정에 확신도가 남아 사람이 검토·수정할 수 있습니다. 규칙=결정적 규칙  유사도=문자열 유사도 사용  사람=사용자 확인·수정 지점

R4처지사 정규화규칙 유사도 순서대로: ① 별칭 맵(원문 또는 "I열|J열" 복합키) ② 정확 일치 ③ 괄호·공백 제거 후 일치 ④ 접두 관계(후보 유일할 때만) ⑤ 유사도 ≥90 ⑥ J열(부서명(부)) 텍스트에서 지사명 탐지. 전부 실패 → 미매핑(강제 귀속 안 함, 리포트 보고).
R5후보 좁히기규칙 매칭 후보는 (예산과목 × 처지사)가 같은 계획행으로 한정. 다른 과목·지사로 잘못 귀속될 가능성을 구조적으로 차단.
R6참조전표번호 묶음규칙 같은 참조전표번호 = 하나의 내역. 묶음 안에서 |금액| 최대 전표의 텍스트를 대표 사업명으로 사용. → 인지세·수수료 등 부대비용 전표가 본 대금 전표를 따라간다.
R7사업명 유사도 매칭유사도 대표 텍스트 vs 계획 사업명들 WRatio(0~100) 계산 → 최고점 계획행에 묶음 전체 귀속. 동점이면 연예산 큰 사업 우선.
R8그룹 정책(기본)규칙 (과목×지사)에 계획행이 있으면 유사도가 낮아도 최고점 행에 귀속하되 임의귀속으로 표시(지사·과목 소계는 정확, 사업 배분은 검토 필요). 계획행이 아예 없을 때만 신규.
R9확신도 산출규칙 전표별 확신도 = 유사도/100. 계획행 확신도 = 귀속 전표 평균. <0.8이면 검토 대상(화면·비고에 표시). 수동지정=1.0.
R10신규사업 클러스터링유사도 귀속 안 된 묶음들을 대표 텍스트 유사도 ≥80로 묶어 사업 단위 행 생성. 표기가 조금씩 다른 월별 전표·부호 상쇄(±) 전표가 한 사업으로 묶여 순액 집계.
R11소액 일괄확정규칙 클러스터 |순액| ≤ 2,000천원 → (지사×과목)별 "OO지사 XX과목 집행" 1행으로 묶음.
R12수동 재배정(오버라이드)사람 사용자가 전표를 다른 사업으로 지정하면 그 전표묶음 전체가 이동(확신도 1.0). DB에 기록되어 재실행해도 유지.

3. 핵심: 텍스트 매칭이 실제로 하는 일

3-1. WRatio 유사도란?

rapidfuzz의 WRatio는 편집거리(Levenshtein) 기반 유사도 여러 개(전체 비교·부분 문자열·토큰 정렬·토큰 집합)를 계산해 가장 유리한 값을 취하는 0~100 점수입니다. 띄어쓰기 유무·어순 차이·연도 표기 차이에 강합니다. 학습된 AI 모델이 아니라 문자열 계산식이므로 결과가 항상 동일하게 재현됩니다.

예시 ① (PPT 슬라이드 6 — 용인지사 무정전 용역, 실측값)
계획: 2023년 무정전전원공급설비 유지보수 용역(연간)
ERP : 용인지사무정전전원공급설비유지보수용역 → 65 임계값(80) 미만이지만 후보 중 최고점 → 그룹정책(R8)으로 이 사업에 귀속하고 확신도 0.65·임의귀속 표시(사람 검토 대상) ✔
ERP : 인지세 → 20 텍스트로는 실패하지만…
R6 전표번호 묶음: 인지세 전표는 참조전표번호 4600039903이 본 대금 전표와 같음 → 본 대금 전표(8,072,425원, |금액| 최대)의 텍스트가 대표가 되어 같은 사업으로 함께 귀속 ✔
예시 ② (PPT 슬라이드 7 — 계획에 없는 신규사업, 실측값)
ERP: '23년1월 지능형영상헬멧 클라우드 비용 +146,459원
ERP: 23년1월 지능형영상헬멧 클라우드 비용 −146,459원 (역인식)
ERP: '23년1월 지능형 영상헬멧 클라우드 비용 +146,459원 (최종 집행)
→ (과목×지사)에 계획행 없음 → 신규. 세 전표의 텍스트 유사도가 서로 98이므로 R10이 한 클러스터로 묶어 「지능형영상헬멧 클라우드 비용」 1개 사업, 순액 146,459원으로 집계(상쇄 전표 유실 없음) ✔

‘AI 분류’의 실체 (정확한 이해)
PPT의 “AI를 통해 자동 분류”에 해당하는 부분은 현재 LLM·머신러닝이 아니라 규칙 + 문자열 유사도로 구현되어 있습니다. 이렇게 한 이유: ① 예산 수치는 재현 가능성·감사 추적이 필수(같은 입력→같은 출력) ② 분리망에서 외부 AI API 사용 불가 ③ 23년 검증에서 수기 대비 −0.06%로 충분히 정확. 유사도로 못 잡는 케이스는 확신도로 드러나며 사람이 재배정(R12)하면 DB에 남아 다음 실행에도 유지됩니다.

4. 총액 보존 (검증 불변식)

모든 ERP 전표는 정확히 한 곳에 배정됩니다:
계획집행 + 신규 (종합표 반영) ∪ 미반영(선택 안 된 과목·지사/미분류/미매핑) ∪ 타예산(손익↔자본) ∪ 제외(합계행·타연도)
→ 어떤 조합으로 필터를 걸어도 종합표 + 미반영 + 타예산 + 제외 = ERP 전체가 항상 성립. 전표가 조용히 사라지는 일이 없습니다.
