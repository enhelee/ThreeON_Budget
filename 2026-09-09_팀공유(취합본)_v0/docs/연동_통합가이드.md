## 2. 파일 흐름 (규격 §2 + 현재 구현 겹쳐 봄)

## 4. 착수 전 합의 필요 (미해결 · 통합 blocker)
> 규격 §6이 지적한 항목 + 실측으로 드러난 공백. **아래가 정해지기 전엔 연동 코드 작성 보류**(현재 방침).

1. **투자유형 분류 담당** — 규격은 동료(budget_app)가 `classified_{연도}.csv`(`투자유형_확정` 8종)를 출력하길 기대하나, budget_app PRD_V1은 이를 3단계(표준화)로 미룸. **현재 "나중에 결정"으로 보류.** → 확정 시 budget_app에 분류 모듈 신규 개발 필요.
2. **샘플 파일 미제공** — `data_2025.csv`·`budget_2025.csv`·`classified_2025.csv` 실물이 없어 칸·값 형식 확정 및 정합 검증 불가. **본인이 실제 3파일 샘플 제공 필요.**
3. **`사업코드` 출처** — 규격 §3-4 matched가 요구하나, 우리 계획·실적 어디에도 없음(§3-2 budget 칸에도 없음). matched에 무엇을 넣을지 정의 필요.
4. **`거래처명` 형식** — 규격은 업체 **이름**(예 `(주)○○기공`)이나, zrfm2 원본엔 **공급업체 코드**(숫자)만 존재. 본인의 `data_csv`가 코드→이름을 해석하는지 확인.

추가 방침(2026-07-22 확정):
- **입력은 budget_app 자체 것(raw `zrfm2.XLSX` + 계획본 xlsx)만 사용** — 규격의 `data/budget CSV` 리더는 당장 안 만듦.
- **손익/자본 파일 분리 유지** — 규격의 연도통합 파일명과 다른 채로 진행(통합 시 파일명 재합의).

## 4-1. 코드화 완료 — 연동 어댑터 `spec_io.py` (2026-07-22)
규격 CSV 계약을 **실제 코드로 구현**했다(동료 코드와 합칠 때 기준). `budget_app/src/budget/spec_io.py`.

| 함수 | 방향 | 설명 |
|---|---|---|
| `write_data_csv(zrfm2, out, year)` | 우리→규격 | zrfm2 → `data_{연도}.csv`(원 단위) |
| `write_budget_csv(plan, out)` | 우리→규격 | 계획본 → `budget_{연도}.csv`(부서 칸 `\n` 포함) |
| `write_matched_csv(erp_annotated, out)` | 우리→규격 | 매칭결과 → `matched_{연도}.csv`(사업코드 공란=gap) |
| `write_classified_csv(erp_annotated, out, classifier=None)` | 우리→규격 | → `classified_{연도}.csv`(투자유형 훅, 기본 `미분류`) |
| `read_data_csv(path)` / `read_budget_csv(path)` | 규격→우리 | 본인이 CSV를 넘겨줄 때 내부 모델로 수용(원→천원 환산) |
| `dept_map_from_budget` / `resolve_dept_by_code` | 보조 | 부서코드 앞3자리→처지사(규격 §6-3) |

- 단위 변환(원↔천원)·컬럼 매핑·부서코드 매핑을 코드로 고정. 테스트 `tests/test_spec_io.py`(10개) 포함, 앱 전체 **71 passed**(rev13).
- **gap은 코드에 명시**: `투자유형_확정`=classifier 훅(미정→`미분류`), `사업코드`=공란, `거래처명`=공급업체 코드.
- **샘플 산출물**: `budget_app/output/연동샘플/`에 `data_2025.csv`·`budget_2025_자본.csv`·`matched_2025_자본.csv`·`classified_2025_자본.csv` 실제 생성(동료에게 포맷 실물로 제시 가능).
- 아직 **엔진에 배선하지 않음**(입력은 우리 것 유지 방침). 합의(§4) 후 `read_*`를 매칭 엔진 입구에 연결하면 됨.

## 5. 합의 후 통합 방식 (권장 설계)
budget_app의 **검증된 매칭 엔진을 유지**하고, 앞뒤에 **얇은 "연동 어댑터" 계층**만 추가한다.
```
[data_{연도}.csv, budget_{연도}.csv]
   → (어댑터) 규격 칸 → budget_app 내부 DataFrame(loaders.PLAN_COLUMNS / ERP 스키마)
   → matching.match_actuals (기존 엔진, 총액 유실 0)
   → (어댑터) 내부 결과 → classified_{연도}.csv / matched_{연도}.csv (규격 포맷)
```
- **금액**: 경계에서 원↔천원 변환(우리 내부 천원, 규격 원). 우리 matched엔 이미 `금액원` 존재.
- **손익/자본**: 계정과목으로 판별하거나 파일 분리 유지(§4 방침) 중 합의값 적용.
- **사업장 코드→처지사**: `budget_{연도}.csv`의 `예산귀속\n부서명(처.지사)`↔`예산귀속 \n부서코드`로 (앞 3자리) 매핑표를 어댑터가 자체 구성(§6-3 규칙과 동일).

이 방식은 기존 테스트/불변식(종합표 총액=ERP 전체)을 깨지 않는다.
