## 4. 운영 DB 정리 (10-19 실행)

- 화면이 읽는 것은 (연도, 손익|자본)별 최신 실행과 (계획|ERP, 연도)별 최신 데이터셋뿐. 나머지 — 옛 실행 22회분(전표 매칭
  277,532 · 사업 집계 19,113 · 실행 22)과 대체된 데이터셋 5개(ERP 19,700 · 계획 3,906 · 데이터셋 5) — **320,278행 삭제**.

  (전망 표·표준화는 캐시 만료 후 재계산본으로 재확인).

## 7. 다시 재는 법

- **Server-Timing**: 브라우저 개발자 도구 → Network → 요청 → Timing. `app`(서버 전체) · `db`(질의 합, `queries=`) · `conn`(연결, `connections=`).
- **Aside 실측**: 로그인은 사람이 한다. 화면 전환 시간 = 해시를 바꾸고 `#busy` 오버레이가 사라질 때까지. 2분 넘는 측정은
  페이지 안에서 백그라운드로 돌리고 폴링(Aside REPL 120초 제한). Aside 는 `/healthz` 요청을 막는다 — 홈 «시스템 확인 불가»는 Aside 한정.
- 배포 직후 첫 요청 한 번은 DB 스키마 확인으로 ~4초 더 걸린다(프로세스당 1회).
- **로컬 비교**: 실DB 사본 + 운영 지연 흉내(연결 550ms · 질의 75ms, `init_db` 뒤부터). 운영 대비 ±20%. Render CPU·데이터 전송은 재현 못 한다.
