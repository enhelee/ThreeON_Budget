# 사내 서버 이관 가이드 — 이미지 파일 하나 + `.env` 하나 (2026-09-20, Phase 6-9)

> 대상: 인터넷이 없는(분리망) 사내 서버에 이 앱을 올리고 운영하는 사람.
> 전제: Phase 6-8 로 컨테이너 안에는 **uvicorn 프로세스 하나**뿐이다. Caddy·Streamlit·supervisord 는 없다.
> 스크립트: `deploy/onprem/` — Linux 는 `.sh`, Windows 는 `.ps1`. **절차는 같고 파일만 두 벌**이다.
> 데이터 이전(Supabase → 사내 PostgreSQL)은 이 문서에 없다 — 별건([다음_할_일_체크리스트.md](다음_할_일_체크리스트.md) 5단계).

---

## 0. 한눈에

```
인터넷 PC (git clone 가능)                         사내 서버 (인터넷 없음)
──────────────────────────────                    ────────────────────────────────
build_image.{sh,ps1}                               load_and_run.{sh,ps1} <tar.gz>
  docker build (--build-arg APP_COMMIT=<커밋>)       체크섬 → .env 검사 → docker load
  docker save → threeon-budget_<커밋>.tar.gz          → latest 태그 → compose up -d --no-build
  .sha256                                            → /healthz 대기(90초)
       │                                           check.{sh,ps1}
       │   반입(USB·반입 승인):                       상태 · /healthz · 보안 헤더 · 볼륨 · 로그
       │   tar.gz + .sha256 · deploy/ · .env
       └───────────────────────────────────────►
```

반입 파일은 셋이다: **이미지(tar.gz + .sha256)** · **`deploy/` 폴더**(compose 와 스크립트) · **`.env`**. 그 외 저장소 전체는 서버에 필요 없다.

## 1. 준비물

| 어디 | 무엇 | 비고 |
|---|---|---|
| 인터넷 PC | Docker Engine 또는 Docker Desktop, git | 빌드용. 이미지 크기 약 400~500MB(압축 후) |
| 사내 서버 (Linux) | Docker Engine 24+ 와 compose 플러그인(`docker compose version` 이 v2) | 권장 |
| 사내 서버 (Windows) | **Docker Desktop(WSL2 백엔드)** | 리눅스 이미지라 WSL2 가 필요하다. Windows Server 라면 리눅스 VM 한 대가 더 단순할 수 있다 |
| 서버 자원 | CPU 2 · RAM 2GB · 디스크 5GB(이미지 1.5GB + 데이터) | pandas 계산이 잠깐 1GB 를 쓴다 |
| 네트워크 | 팀 PC → 서버 `HOST_PORT`(기본 8080) | HTTPS 는 §7 |

## 2. 인터넷 PC 에서 이미지 만들기

```bash
# Linux/macOS
git clone https://github.com/enhelee/ThreeON_Budget && cd ThreeON_Budget/2026-09-09-team-package-v0
bash deploy/onprem/build_image.sh            # → dist/threeon-budget_<커밋>.tar.gz + .sha256
```
```powershell
# Windows
git clone https://github.com/enhelee/ThreeON_Budget; cd ThreeON_Budget\2026-09-09-team-package-v0
powershell -ExecutionPolicy Bypass -File deploy\onprem\build_image.ps1
```

스크립트가 하는 일: `docker build`(Node 로 프론트 빌드 → python:3.12-slim 에 pip 설치, **처음 5~10분**) → `docker save` → gzip → SHA256. **커밋 해시를 이미지에 굳혀** `/healthz` 의 `commit` 이 사내에서도 찍힌다 — 이것이 «지금 뜬 게 어느 버전인가»의 유일한 근거다.

> 사내 TLS 프록시 뒤의 PC 에서 빌드가 안 되면: 6-8 이후 Dockerfile 은 GitHub 릴리스 자산을 받지 않는다. 남은 외부 접근은 Docker Hub(`node:24-alpine`·`python:3.12-slim`)·npm·pip 뿐이니, 그 셋의 프록시/미러 설정만 보면 된다.

## 3. 반입

USB 등으로 아래를 서버의 한 폴더(예: `/opt/threeon` 또는 `C:\threeon`)에 놓는다.

```
threeon/
├─ threeon-budget_<커밋>.tar.gz
├─ threeon-budget_<커밋>.tar.gz.sha256
├─ deploy/                 ← 저장소의 deploy/ 폴더 그대로 (docker-compose.yml · onprem/)
└─ .env                    ← .env.example 을 복사해 작성 (아래)
```

`.env` 최소 세 줄:
```
APP_PASSWORD=팀공용비밀번호-12자이상
SECRET_KEY=(python -c "import secrets; print(secrets.token_urlsafe(48))" 결과)
COOKIE_SECURE=0            # 사내 http 면 0. HTTPS 프록시 뒤면 1 (§7)
```
포트를 바꾸려면 `HOST_PORT=8090`. PostgreSQL 컨테이너를 같이 쓰려면 `PG_PASSWORD` 와 `DATABASE_URL=postgresql://budget:<PG_PASSWORD>@postgres:5432/budget`. 나머지 키의 뜻은 `.env.example` 에 있다.

> ⚠ `.env` 는 이 폴더(compose 가 `../.env` 로 읽는 위치 = `deploy/` 의 부모)에 둔다. 저장소 로컬 개발의 `app/.env` 와는 **다른 자리**다.

## 4. 서버 기동

```bash
# Linux
cd /opt/threeon
bash deploy/onprem/load_and_run.sh threeon-budget_<커밋>.tar.gz          # SQLite(볼륨) 모드
bash deploy/onprem/load_and_run.sh threeon-budget_<커밋>.tar.gz --pg     # + PostgreSQL 컨테이너
```
```powershell
# Windows
cd C:\threeon
powershell -ExecutionPolicy Bypass -File deploy\onprem\load_and_run.ps1 -Tar threeon-budget_<커밋>.tar.gz [-Pg]
```

다섯 단계 — ① 체크섬 ② `.env` 필수 키 ③ `docker load` → `threeon-budget:latest` 태그 ④ `docker compose up -d --no-build` ⑤ `/healthz` 가 200 을 낼 때까지 최대 90초. 끝나면 `{"ok":true,…,"commit":"<커밋>","db":"sqlite|postgresql"}` 을 찍는다.

**`--no-build` 가 핵심이다.** 서버에는 인터넷이 없으므로 빌드가 걸리면 pip·npm 이 밖으로 나가려다 조용히 오래 실패한다. compose 에도 `pull_policy: never` 를 둬서 이미지를 못 찾으면 레지스트리를 뒤지지 않고 바로 실패한다.

접속: `http://<서버IP>:8080/` → 로그인 게이트(팀 비밀번호 + 이름) → 작업공간.

## 5. 점검

```bash
bash deploy/onprem/check.sh              # Linux
```
```powershell
powershell -ExecutionPolicy Bypass -File deploy\onprem\check.ps1     # Windows
```

보는 것: 컨테이너 헬스(`healthy`) · `/healthz` 의 `commit`(7자리가 비어 있으면 `build_image` 로 만든 이미지가 아니다) · 보안 헤더 3종(`x-content-type-options`·`x-frame-options`·`referrer-policy` — 6-8 이후 프록시 없이 앱이 직접 낸다) · 볼륨 존재 · 디스크 · 최근 로그. 하나라도 빠지면 종료코드 1.

## 6. 운영

### 백업
| 모드 | 백업 대상 | 방법 |
|---|---|---|
| SQLite(기본) | 볼륨 `budget_data` 의 `budget.db` 1개 | `docker run --rm -v threeon_budget_data:/d -v "$PWD":/b alpine tar czf /b/budget_$(date +%F).tgz -C /d .` |
| PostgreSQL | DB | `docker exec threeon-postgres pg_dump -U budget budget > budget_$(date +%F).sql` |

앱 상태는 전부 DB 에 있다(구성·마감·전망 상태 9종·학습 레지스트리). `output/` 은 재생성 가능한 산출물이라 백업 대상이 아니다.

### 업데이트
인터넷 PC 에서 `build_image` 로 새 tar.gz → 반입 → **같은 `load_and_run`** 을 다시 실행. 볼륨은 그대로라 데이터가 남는다. 컨테이너 교체 중 10~20초 접속이 끊긴다.

### 롤백
이전 이미지 태그가 서버에 남아 있다(`docker images threeon-budget`).
```bash
docker tag threeon-budget:<이전커밋> threeon-budget:latest
docker compose -f deploy/docker-compose.yml up -d --no-build
```
DB 스키마는 앞으로만 간다(`init_db` 가 없는 표·열을 추가). 되돌린 앱이 새 열을 모르는 것은 괜찮지만, **새 앱이 표 구조를 바꾼 뒤라면 롤백 전에 백업을 복원**한다.

### 재시작·중지·로그
```bash
docker compose -f deploy/docker-compose.yml restart app
docker compose -f deploy/docker-compose.yml down          # 컨테이너만. 볼륨(데이터)은 남는다
docker compose -f deploy/docker-compose.yml logs -f app
```
`restart: unless-stopped` 라 서버가 재부팅되면 알아서 올라온다. Windows 는 Docker Desktop 의 «로그인 시 시작»을 켜 둔다.

### 비밀번호 교체
`.env` 의 `APP_PASSWORD` 수정 → `restart app`. `SECRET_KEY` 를 바꾸면 모든 로그인이 풀린다.

## 7. HTTPS

앱은 http 로만 듣는다. HTTPS 가 필요하면 **사내 프록시(nginx·IIS·사내 L7)** 를 앞에 두고 `HOST_PORT` 로 넘긴다. 그때 `.env` 에 `COOKIE_SECURE=1` — 안 그러면 세션 쿠키가 https 에서만 붙는 `Secure` 속성 없이 나가고, 반대로 http 인데 1 이면 쿠키가 안 붙어 로그인이 안 된다. 프록시는 `X-Forwarded-Proto` 를 넘겨야 한다(uvicorn 이 `--proxy-headers` 로 읽는다).

## 8. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| `load_and_run` 이 «.env 가 없습니다» | `.env` 위치가 `deploy/` 의 부모 폴더인지 확인 |
| `/healthz` 가 90초 내 응답 없음 | `docker compose logs app`. 포트 충돌이면 `.env` 의 `HOST_PORT` 변경. Windows 는 WSL2 메모리 부족일 수 있음(`.wslconfig` 에 `memory=4GB`) |
| compose 가 이미지를 «pull» 하려 함 | `docker load` 가 실패했거나 태그가 안 붙음. `docker images threeon-budget` 으로 확인 후 `docker tag … :latest` |
| 로그인 후 바로 풀림 | `SECRET_KEY` 가 비어 임시 키로 기동됨(재시작마다 바뀜). `.env` 에 채우고 `restart` |
| 로그인 자체가 안 됨(쿠키) | http 인데 `COOKIE_SECURE=1`. 0 으로 |
| `check` 가 «commit 이 비어 있습니다» | `docker build` 를 직접 돌린 이미지. `build_image` 스크립트로 다시 만들 것(`--build-arg APP_COMMIT`) |
| `/healthz` 의 `db` 가 기대와 다름 | `DATABASE_URL` 이 비면 sqlite, 있으면 postgresql. `--pg` 로 띄웠는데 sqlite 면 `.env` 의 `DATABASE_URL` 누락 |

## 9. 이 문서의 검증 상태

| 단계 | 상태 | 근거 |
|---|---|---|
| 문법·구조 | ✅ | `bash -n` · PowerShell 파서 · `app/tests/test_onprem_package.py` |
| 스크립트 논리 전 구간 (bash · PowerShell 둘 다) | ✅ 2026-09-20 | **docker 대역(shim) 시뮬레이션** — `docker` 명령만 가짜로 바꿔 끼우고 `build_image → 반입 폴더 구성 → load_and_run → check → down` 을 실제로 실행. 체크섬 생성·검증, `.env` 검사, `Loaded image:` 파싱, `latest` 태그, `up -d --no-build` 인자, 헬스체크 대기(**진짜 uvicorn** 을 띄워 `/healthz` 가 `commit` 을 냄), `check` 의 헤더 3종까지 확인. 부정 경로 5건(`.env` 없음 · 체크섬 불일치 · `--pg` 인데 `PG_PASSWORD` 없음 · `APP_PASSWORD` 비어 있음 · tar 경로 오타) 모두 종료코드 1 + 안내 메시지, `up` 호출 0건 |
| 교차 OS (Windows 빌드 → Linux 서버) | ✅ 2026-09-20 | Windows `build_image.ps1` 산출물을 bash `load_and_run.sh`·`check.sh` 로 적재·기동·점검. GNU tar 가 PATH 에 먼저 잡힌 환경에서도 빌드 성공 |
| 이때 잡은 결함 3건 | 고침 (테스트 고정) | ① Windows `.sha256` 이 CRLF → Linux `sha256sum -c` 실패 → LF ② `tar -czf x.tar.gz x.tar` 가 «docker tar 를 담은 tar» 를 만들어 **실제 `docker load` 가 못 읽었을 것** → .NET `GZipStream` 으로 docker tar 를 직접 gzip(= bash 의 `docker save \| gzip`) ③ `tar.exe` 가 PATH 에 따라 GNU tar 로 잡혀 `C:\` 콜론을 원격 호스트로 해석 → 외부 도구 의존 제거 |
| **실제 Docker** (`docker build/save/load`, compose 기동, 볼륨) | ⬜ 미실행 | Docker 있는 PC 에서 한 번. 결과를 이 표에 |

시뮬레이션이 보장하지 않는 것: Dockerfile 빌드 성공 여부(Render 빌드로는 검증됨), `docker load` 의 실제 출력 형식, WSL2 환경의 포트 노출. 이 셋은 실제 실행에서만 드러난다.
