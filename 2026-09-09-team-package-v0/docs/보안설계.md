# 보안 설계 — 실데이터를 팀원만 다루는 공개 URL (2026-09-09 · 현행화 2026-09-21)

> 전제(사용자 결정): 합성 데이터가 아닌 **실제 예산·실적 데이터**를 쓰되, **팀원만** 접근해 업로드·수정한다. 인증은 **공용 비밀번호 1개**이며 수정 이력은 남아야 한다. 지금은 무료 클라우드, 최종은 사내 분리망.

## 2. 인증 흐름(budget_app)

```
브라우저 ─ GET / ─▶ index.html (정적, 데이터 없음 · /app/ 은 301 로 여기로)
        ─ GET /api/auth/status ─▶ {enabled:true, logged_in:false} → 로그인 오버레이
        ─ POST /api/login {password, name} ─▶ 비밀번호 비교(hmac.compare_digest) → Set-Cookie budget_session=서명({op:name})
        ─ /api/* (쿠키) ─▶ 미들웨어 검증 → request.state.operator = name
        ─ POST/DELETE ─▶ 응답 후 audit_log INSERT (operator, method, path, status, 요약)
        ─ 401 login_required ─▶ 프론트가 오버레이 재표시
```
- `APP_PASSWORD`가 비어 있으면 인증이 꺼지고 작업자는 `local`로 기록된다(사내망 개발용). **공개 배포에서는 절대 비우지 않는다**(entrypoint가 경고).
- 실패한 로그인도 `audit_log`(401, 입력한 이름)에 남는다 → 무차별 시도 감지.
- 로그아웃은 쿠키 삭제. 전원 강제 로그아웃은 `SECRET_KEY` 교체(재배포).

## 3. 3·4단계(표준화·중장기 전망) 게이트
Phase 6 이전에는 동료의 별도 앱이라 앱 밖(엣지 프록시 기본인증)에서 감쌌고, 그 안의 저장에는 감사 로그가 없었다. 6-6 에서 5번 탭으로 흡수되어 **같은 로그인·같은 `AuthAuditMiddleware`** 를 지난다 — 팩터·정비등급·본사배분 등 상태 9종의 변경(`PUT /api/forecast/state/*`)도 `audit_log` 에 작업자와 함께 남는다. 상태는 파일이 아니라 DB(기준연도 축)에 있어 배포·재시작에도 남는다.

## 4. 비밀 관리 규칙
1. `.env`는 각 실행 위치에 하나(로컬 `budget_app/.env`, Compose는 패키지 루트 `.env`). 절대 커밋하지 않는다. `.env.example`만 커밋.
2. 값 생성: `SECRET_KEY` = `py -c "import secrets;print(secrets.token_urlsafe(48))"`; `APP_PASSWORD` = 12자 이상 문구.
3. 전달: 사내 메신저 **비밀 메모/1회성 링크**. 카톡 일반 채팅·이메일 본문 금지.
4. 교체 주기: 팀원 변동 즉시, 그 외 분기 1회. 교체 후 Render 재배포 + 팀 공지.
5. Supabase 연결문자열에는 DB 비밀번호가 들어 있다 — `.env`·Render 환경변수 외에는 어디에도 적지 않는다(문서·이슈·스크린샷 주의).

## 5. 데이터 보관·삭제
- 무료 배포 기간의 실데이터는 **임시**다. 검토 종료 시 Supabase 표를 비우거나 프로젝트를 삭제하고, 사내 서버로 이전한다(배포가이드 §3.3).
- 백업: SQLite 모드는 `budget.db` 1파일, PG 모드는 `pg_dump`. 모델·학습데이터도 같은 DB에 있어 별도 백업 불필요.
- 감사 로그는 삭제 API가 없다(의도). 보존 기간이 필요하면 DB에서 직접 정리.
