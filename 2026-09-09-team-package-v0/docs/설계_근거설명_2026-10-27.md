# 근거 설명 자동 초안 (B) — 2026-10-27

> 경진대회 전략 B. 검토 큐 한 줄을 «사람이 읽는 근거 문장»으로 바꾸고, 차이 사유 칸에 초안으로 넣는다.
> 코드 `app/src/budget/explain.py` · API `GET /api/review-explain` · 화면 `views/review.js`(«근거·초안 ▾»).

## 1. 왜

차이 사유를 백지에서 쓰면 담당자가 전표를 다 열어 «무엇이 얼마나»부터 다시 센다. 사유 미입력이 1,405건이었던 이유 중 하나다.
분석 결과에는 이미 사실이 다 있다 — 계획·실적, 큰 전표, 전년 같은 사업, 매칭 근거. 그걸 문장으로 모으기만 해도 사유의 절반은 쓰인다.

## 2. 원칙

- **LLM 없이 규칙만.** 폐쇄망 그대로 돈다. 같은 입력이면 같은 문장이 나오고, 문장마다 근거 숫자가 있다(«설명 가능한 AI»).
- **원인은 단정하지 않는다.** 전표 글자·귀속 모양으로 짐작한 것은 «추정 원인»으로만 보여 준다.
- **저장은 사람이.** «초안을 사유 칸에 넣기»는 칸을 채우기만 한다. 고친 뒤 [저장](또는 Enter)해야 사유가 된다.
- **숫자는 바꾸지 않는다.** 읽기 전용 API다. 마감 연도에도 근거를 볼 수 있고, 사유는 원래처럼 마감 연도에도 저장된다.

## 3. 문장 (천원 → 억 원·백만 원으로 읽기 쉽게)

| 순서 | 문장 | 재료 |
|---|---|---|
| ① | «계획 25.5억 원 대비 67.6억 원 집행(266%, 42.1억 원 초과).» / «미시행 — 계획 … 전액이 집행되지 않았다.» / 음수 실적 | 사업 줄 계획·실적 |
| ② | «전표 5건 중 상위 3건(«…» 62.9억 원, …)이 실적의 100%.» | 이 줄 전표, 금액 절대값 큰 순 |
| ③ | «전년 같은 사업(«…») 실적 20.7억 원 대비 +1%.» (±50% 넘으면 «2.3배»·«0.6배») | 전년 최신 분석, 같은 예산·지사, 연도 글자를 뺀 사업명 유사도 ≥0.80, 설비가 다르면 제외 |
| ④ | «매칭 근거: 학습 39건 · 재배정 10건 (확신도 0.8 미만 …)» | 전표 매칭 근거 — **화면에만**, 사유 초안에는 넣지 않는다(사유는 «왜 썼나») |

**추정 원인** (걸린 것 모두)

| 규칙 | 추정 |
|---|---|
| 전표 글자 «이월·전년도·미지급» | 전년 이월분 집행 |
| «기성» | 기성(분할) 대금 집행 |
| «정산·설계변경» | 정산·설계변경 증액 |
| «선급» | 선급금 집행 |
| «긴급·돌발·고장·파손·복구» | 긴급·돌발 정비 |
| «취소·반제·역분개·대체» | 취소·대체 전표 |
| 확신도 0.8 미만 전표가 초과액의 50% 이상 | 다른 사업 전표 혼입 가능 |
| 재배정 전표가 실적의 50% 이상 | 의도한 통합 집행인지 확인 |
| 음수 전표가 실적의 10% 이상 | 취소·재전기 전표 포함 |

사유 초안 = ①②③ + «추정 원인: …». 500자(사유 칸 한도)에서 자른다.

## 4. 운영 사본 확인 (2025, 검토 큐 상위 40건)

- 전년 같은 사업을 찾은 줄 32/40. 못 찾은 줄은 대부분 설비가 다른 사업만 있는 경우(GT ↔ 제어·전기)로, 일부러 건너뛴 것이다.
- 예: 상위 3위 «… 정기점검보수공사» — 계획 1.1억 원에 22.5억 원, 전표 4건이 모두 확신도 0.8 미만 → «다른 사업 전표 혼입 가능 — 확신도 낮은 전표가 초과액의 100%». 실제로 정밀도 측정에서 드러난 약점과 같은 모양이다.
- 화면: «근거·초안 ▾» → 근거·추정 → «초안을 사유 칸에 넣기» → 고쳐서 Enter → «사유 입력됨». 콘솔 오류 없음.
