## 1. 문제

분석이 끝나면 사람이 볼 것이 세 갈래로 흩어져 건수만 보였다.

| 갈래 | 운영 2025 건수 | 있던 곳 |
|---|---|---|
| 이상 알림(급증·예산 초과·과다 귀속·음수·미매칭) | 186건, 높음 171건 | 2번 실적 집계 |
| 차이 사유 미입력(집행률 ±20%p) | 1,405건 | 3+ 상세 |
| 저확신 귀속(확신도 0.8 미만) | 표시만 | 3+ 상세 노란 배지 |

메인 «다음 할 일»에 «171건 · 1,405건»이 그대로 떠서 어디서 시작할지 모르고, 보고·심사 자리에서는 «일이 안 끝났다»로 읽혔다. 같은 사업이 세 갈래에 겹쳐 나오기도 했다.

## 2. 해법 한 줄

**사업 한 줄을 검토 단위로 묶고, 그 줄에 걸린 돈 × 위험 가중으로 줄을 세운다.** 남은 검토 금액의 80% 를 덮는 건수와 처리 진행률(금액 기준)을 함께 보여 주고, 한 줄씩 1클릭으로 닫는다.

참고한 제품 패턴: Ramp 회계 에이전트의 «Ready / Needs review» 큐와 저확신 노랑 표시, 파레토(80/20) 우선순위, Linear 의 키보드 이동.

## 3. 계산 규칙 (`app/src/budget/review_queue.py`)

### 3-1. 이유와 검토 금액(천원)

| 이유(code) | 조건 | 검토 금액 | 위험 가중 |
|---|---|---|---|
| 과다 귀속(`overload`) | 이상 알림의 «과다 귀속»과 같은 판정(`alerts.compute_alerts` 결과를 그대로 받음 — 기준을 두 곳에 두지 않는다) | 실적 − 계획 | 1.5 |
| 음수 실적(`negative`) | 실적 ≤ −1,000 | \|실적\| | 1.5 |
| 저확신 귀속(`lowconf`) | 확신도 0.8 미만 전표 합 ≥ 10,000(1천만 원) | 그 전표 합 | 1.2 |
| 차이 사유(`variance`) | `dbm.is_variance`(집행률 80% 미만 또는 120% 초과, 계획 있는 줄) — 과다 귀속이면 그쪽으로 | \|실적 − 계획\| | 1.0 |

- 한 줄에 이유가 여럿이면 **검토 금액 = 가장 큰 값**(같은 돈을 두 번 세지 않는다), **우선순위 점수 = 가중 금액 중 가장 큰 값**.
- 과다 귀속·음수가 먼저 오는 이유: 숫자 자체가 틀렸을 수 있다(설명보다 정정이 먼저).
- 위험도 «높음» = 검토 금액 5천만 원 이상(이상 알림과 같은 선).
- 같은 키(예산·과목·지사·사업명)의 동명 줄은 합친다 — 차이 사유·승인이 이름으로 붙기 때문.
- 맥락(순위에는 안 씀): 과목 단위 급증·예산 초과 문장, 그리고 귀속 금액의 50% 이상이 사람이 재배정한 전표면 «의도한 귀속이면 승인» 힌트.

### 3-2. 처리 상태

| 상태 | 언제 | 처리됨으로 셈 |
|---|---|---|
| `open` | 아직 아무것도 안 함 | 아니오 |
| `noted` | 차이·과다·음수 이유가 있는 줄에 차이 사유가 있다 | 예 |
| `approved` | «이상 없음»을 눌렀고, 승인 때 실적과 지금 실적이 1천원 이내로 같다 | 예 |
| `stale` | 승인했지만 재분석으로 실적이 바뀌었다 — 다시 본다 | 아니오 |
| `moved` | 이 줄에서 나가거나 들어올 전표 재배정을 저장했고, 아직 «분석 반영» 전 | 예 |

- 저확신만 걸린 줄은 사유로 닫히지 않는다 — 질문이 «설명»이 아니라 «귀속이 맞나»라서 승인이나 재배정으로 닫는다.
- `moved` 판정 시각 비교는 헤더 «분석 반영 N» 배지(`server._pending_data`)와 같은 «초과(>)»다. 두 표시가 어긋나지 않게 했다.

### 3-3. 요약

- 정렬: 미처리 먼저(점수 큰 순), 처리된 것은 뒤. 미처리에만 순위(1부터).
- 커버율 곡선: 미처리를 순위대로 볼 때 남은 검토 금액의 누적 비율. `n80` = 80% 에 처음 닿는 건수.
- 진행률 = 처리된 검토 금액 / 전체 검토 금액.
- 화면도 같은 셈을 JS(`views/review.js rqSummarize`)로 한다 — 처리 직후 바로 고쳐 그리고, 서버 값이 오면 덮는다.

### 3-4. 추천 재배정(정확도 우선)

같은 예산·지사·과목 안의 다른 계획 사업 중 전표 글자를 «분명히 더 닮은» 곳만 추천한다.

- 유사도: `normalize.learn_key` 로 정규화한 전표 글자와 사업명의 RapidFuzz WRatio(0~1).
- 조건: 유사도 ≥ **0.75**, 지금 붙은 사업보다 **0.15** 이상 더 닮음, 그리고 **설비·연도 충돌 없음**(`conflicts`).
  - 설비 묶음: GT·가스터빈 / ST·증기터빈 / 연료전지 / SRF / DH / 보일러·HRSG·PLB / 전기 / 기계 / 계측·제어 / 건축·건물.
  - 양쪽에 다 적혀 있고 겹치지 않을 때만 막는다. 한쪽에만 있으면 판단하지 않는다.
- 동점에 가까우면 잔액(계획 − 실적)이 그 전표를 받을 수 있는 곳을 아주 조금(+0.03) 앞에 둔다.
- 덜 집행된 줄은 반대 방향(«이리로 가져오기»): 같은 과목 다른 사업에 붙었지만 이 사업 이름을 더 닮은 전표.
- 처음 기준(0.60 / 0.05, 충돌 검사 없음)에서는 운영 사본에서 «GT LTSA 1월 비용인식 → 연료전지 LTSA», «2025년 판교 정기점검 → 2024년 판교 정기점검» 같은 오추천이 나왔다. 기준을 올린 뒤 상위 250줄에서 추천 1건 — «발전용보일러공기예열기세정공사» 전표가 «소방설비 보수공사»에 붙어 있던 것(같은 이름의 계획 사업, 유사도 1.00). **누락이 오추천보다 낫다**는 판단이다. 추천이 없는 전표는 잔액 큰 순 사업 목록에서 골라 옮긴다.

## 4. 저장

| 표 | 키 | 값 | 비고 |
|---|---|---|---|
| `review_ack`(새) | year, budget, 예산과목, 처지사, 사업명 | actual(승인 때 실적 천원), operator, updated_at | PG 는 `dbcore.REPLACE_TABLES` 로 upsert. 사업명을 바꾸면 `rename_biz_references` 가 따라 옮긴다 |
| `variance_note`(기존) | 같은 키 | note | 사유 칩도 여기 저장 |
| `override`(기존) | 전표 | target_name, target_dept | 큐의 재배정도 같은 API |

DB 조회는 SQL 에서 묶어 줄 수만큼만 받는다(`db.basis_by_line` — 줄별 전표 합·저확신 합·사람 재배정 합 한 번에, `db.moved_lines`). ⚠ `LIKE '재배정%'` 처럼 «%» 를 SQL 글자로 쓰면 PostgreSQL(psycopg)이 자리표시자로 읽어 깨진다 — 무늬는 매개변수로 넘긴다(테스트로 고정).

## 6. 화면 (`app/web/src/views/review.js` · `review_actions.js`)

- 요약 한 줄: 남은 검토 건수 · 남은 금액 · 처리 건수/금액 · 위험 높음(rev34 — 처음 둔 큰 머리 카드·파레토 곡선·보기 단추는 사용자 결정으로 뺐다. 80% 건수는 서버 요약 `n80` 에 그대로 있다). 목록은 20건 + «더 보기».
- 거르기: 이유 칩(건수) · 예산 · 지사 · 미처리/처리됨/전체.
- 카드: 순위 · 위험·이유·상태 배지 · 사업명 · 계획→실적·집행률(80~120 초록/80 미만 노랑/120 초과 빨강) · 계획 눈금 대 실적 막대 · 이유 문장 · 맥락 · 검토 금액.
- 동작: **✓ 이상 없음** · 방향별 **사유 칩**(초과 / 미달 / 미시행, 누르면 저장) · 직접 입력 · **전표·재배정**(추천대로 옮기기 · 사업 고르기 · 이리로 가져오기 · 추천 일괄) · **3+ 상세 →**(그 지사·과목·사업으로 걸러 전표를 펼친다).
- 처리된 카드는 옆으로 빠지고(동작 줄이기 설정이면 바로) 진행률이 즉시 오른다. 0.6초 뒤 서버 계산으로 덮는다. 실패하면 되돌린다.
- 단축키: J·K 이동 · A 승인 · 1~5 사유 칩 · E 전표(입력칸 안에서는 Enter 저장 · Esc 취소).
- 메인 «다음 할 일»: 알림·차이 사유 두 줄 대신 «검토 큐 — 남은 N건 · 금액 (처리 M건)» 한 줄. 큐를 못 받으면 예전 두 줄. 실적 집계 알림 패널에도 «검토 큐에서 처리 →».
- 색은 한난 토큰만(잉크 곡선 · ok 진행 · line 격자). 설명문 대신 숫자·상태 줄, 설명은 «? 도움말».
