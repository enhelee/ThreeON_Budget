## 0. 구성 한눈에

```
                 https://<주소>/
 ┌──────── uvicorn (:$PORT, 프로세스 하나 · TLS 는 Render/사내 프록시가 종단) ────────┐
 │  /              SPA (로그인 게이트 → 작업공간 5탭)   Cache-Control: no-cache          │
 │  /assets/*      해시 파일명 자산                     immutable + gzip                  │
 │  /api/*         FastAPI — 공용비밀번호 로그인 + 작업자 이름 + 감사로그                 │
 │  /healthz       {ok, auth, rev, commit, db}  ← 배포 판별은 이 commit 으로              │
 │  /app/*         301 → /  (옛 북마크 보호)                                              │
 └────────────────────────────────────┬───────────────────────────────────────────────┘
                                      │ DATABASE_URL
                         PostgreSQL(Supabase 무료 / 사내 PG)  ← 비우면 SQLite(볼륨)
```
보안 헤더 3종·gzip·자산 캐시는 앱이 직접 낸다(`server.py` 미들웨어, `tests/test_http_hardening.py` 가 고정). 무료 PaaS 든 사내 서버든 같은 이미지다.

| 파일 | 역할 |
|---|---|
| `deploy/Dockerfile` | Node 로 프론트 빌드 → python:3.12-slim + pip. 실데이터·.env·산출물은 `.dockerignore`로 절대 포함 안 됨. `ARG APP_COMMIT` 으로 사내 이미지에도 커밋 해시 |
| `deploy/entrypoint.sh` | 볼륨 폴더 생성 · 환경변수 경고 · `exec uvicorn --host 0.0.0.0 --port $PORT --proxy-headers --no-server-header` |
| `deploy/docker-compose.yml` | 사내 서버: 볼륨 + (선택) PostgreSQL 컨테이너. `pull_policy: never` |
| `deploy/onprem/` | 사내 반입 스크립트(`build_image`·`load_and_run`·`check`, `.sh`/`.ps1`) → [사내이관_가이드.md](사내이관_가이드.md) |
| `deploy/requirements.txt` | 파이썬 의존성(pandas 2.2.3 고정·psycopg 3) |
| 저장소 루트 `render.yaml` | Render Blueprint(무료 웹서비스) |
| 패키지 루트 `.env.example` | 설정 키 목록(값 없음). 로컬은 `app/.env`, Docker 는 패키지 루트 `.env` 로 복사 |

환경변수(비밀은 `.env`/PaaS 대시보드에만): `APP_PASSWORD` `SECRET_KEY` `DATABASE_URL` `SESSION_HOURS` `COOKIE_SECURE` `APP_REV`(+ compose 전용 `HOST_PORT` `PG_*`). 자세한 의미는 `.env.example`.

## 1. 지금 단계 — 무료 공개 배포 (Render + Supabase + GitHub Pages)

### 1.1 플랫폼 검토 결과 (사용자 요청: Render / Vercel / Supabase)

| 후보 | 판정 | 근거 |
|---|---|---|
| **Render Web Service (Docker, Free)** | **앱 배포 — 채택** | Docker 이미지 그대로, HTTPS 자동, GitHub 연동. 제약: 15분 미사용 시 슬립(첫 접속 30~60초), **디스크 비영속**(재배포 시 파일 초기화) → DB는 외부(Supabase). ⚠ Auto-Deploy 가 실제로는 걸리지 않아 병합 뒤 **Manual Deploy** 를 눌러야 한다(2026-09 반복 실측) |
| **Supabase (PostgreSQL, Free)** | **DB — 채택** | 500MB·영속·백업 UI·SSL. 우리 데이터(23·25년 ERP 2.4만 행 + 매칭 이력 정리본 ≈ 20~30MB)에 충분. 7일 미접속 시 프로젝트 일시정지(대시보드에서 재시작). 나중에 Supabase Auth로 **개인 계정** 확장 가능 |
| **Vercel** | **앱은 부적합** | 서버리스 함수(기본 10초·최대 60초 제한), 영속 프로세스 없음 → 분석(16~19초)·파일 산출물이 제한에 걸림. 정적 페이지만 가능 |
| **GitHub Pages** | 소개 사이트용(현재 미사용) | 무료·영구. Phase 5 에서 소개를 SPA 가 흡수해 별도 사이트가 없어졌다 |
| Hugging Face Spaces (Docker) | 대안 | 슬립 없음(48시간 미사용 시 정지), 포트 7860 단일 → 같은 이미지에 `PORT=7860`으로 가능. 디스크 비영속 동일 |
| Northflank 등 상주 컨테이너 호스트 | Phase 6 이후 이전 후보 | 강제 슬립 없음, GitHub 연동. 프로세스가 하나가 된 지금이 옮기기 좋은 시점(사용자 결정 사항) |

### 1.2 실데이터를 공개 클라우드에 두는 문제 — 반드시 읽을 것
사용자 결정은 "가상 데이터가 아닌 **실데이터**를 팀원만 접근해 업로드·수정". 기술적으로는 아래 §2 보안 구성으로 팀 외 접근을 차단하지만, **회사 실적·예산 데이터를 외부 클라우드(Render·Supabase)에 저장하는 것은 사내 정보보호 규정 확인이 먼저**다. 이 문서는 "최종은 사내 서버"를 전제로, 무료 배포 기간을 **팀 검토용 임시 운영**으로 본다. 권장 원칙:
- 공개 배포 기간에는 **필요한 연도만** 업로드하고, 검토가 끝나면 Supabase 테이블을 비우거나 프로젝트를 삭제한다.
- 팀 공용 비밀번호는 12자 이상, 메신저 비밀 메모로만 전달, 팀 변동 시 즉시 교체(Render 환경변수 수정 → 자동 재배포).
- Supabase 대시보드 로그인에 2단계 인증을 켠다(DB 자체 접근 권한이므로 가장 중요).

### 1.3 배포 절차
**A. GitHub 업로드**
1. `2026-09-09-team-package-v0/` 내용을 저장소 `enhelee/ThreeON_Budget`의 새 폴더 `2026-09-09-team-package-v0/`로 올린다(패키지 `.gitignore`가 실데이터를 걸러준다 — 업로드 전 `git status`로 `.env`·`*.db`·`*.csv`가 없는지 확인).
2. Render는 저장소 루트의 `render.yaml`을 찾으므로, 저장소 **루트**에 `render.yaml`을 두고 `dockerContext: ./2026-09-09-team-package-v0` · `dockerfilePath: ./2026-09-09-team-package-v0/deploy/Dockerfile`로 경로만 고친다(패키지 안 `deploy/render.yaml`은 패키지 자체를 루트로 올릴 때의 값).

**B. Supabase**
1. supabase.com → New project(리전 `Northeast Asia (Seoul)`), DB 비밀번호 생성·보관.
2. Project Settings → Database → Connection string → **Transaction pooler(포트 5432)** 문자열 복사, 끝에 `?sslmode=require`.
3. 로컬에서 먼저 검증: `budget_app/.env`에 `DATABASE_URL=…` 넣고 `py scripts/db_check.py` → 표 18개 생성·조회 OK 확인. 기존 SQLite 데이터를 옮길 땐 `py scripts/db_check.py --migrate`(로컬 `data/budget.db` → PG 전체 복사).
   - ✅ PostgreSQL 경로는 **로컬 PostgreSQL 16.4 실서버로 검증 완료**(2026-09-09): 스키마 18표 생성, 실데이터 전체 이전(erp_row 43,840행 등 13표, 16초), 인증·레지스트리 API 테스트 4건, 전체 API 워크로드(overview·status·branches·branch-detail·stats·export-team·analyze·manual-biz·lock 423·learn·audit) 통과. **내보내기 합계가 SQLite와 원 단위까지 동일**(손익 98,554,800,525 · 자본 49,709,177,979). 이 과정에서 PG `REAL`(float4) 정밀도 손실(−50원/+144원)을 발견해 `REAL→DOUBLE PRECISION` 번역을 추가했다 — Supabase에서도 `db_check.py` 첫 실행으로 표를 만들면 자동 적용된다. Supabase는 네트워크·SSL만 다르므로 `db_check.py` 통과 여부만 확인하면 된다.
   - 이전(`--migrate`)은 **대상 표를 비우고 전체 교체**한다(부분 병합 아님). 이력을 줄이려면 먼저 `py scripts/db_정리.py`.

**C. Render**
1. render.com → New → Blueprint → 저장소 선택 → `render.yaml` 인식 → Apply.
2. Environment에 `APP_PASSWORD`(팀 공용), `DATABASE_URL`(Supabase) 입력. `SECRET_KEY`는 자동 생성.
3. 빌드 5~8분(Node 프론트 빌드·pip). 완료 후 `https://threeon-budget.onrender.com/healthz` → `{"ok":true,"auth":true,"rev":…,"commit":"<병합 커밋 7자리>","db":"postgresql"}`. **`commit` 이 `origin/main` 과 같아야 새 배포다** — 정적 파일 타임스탬프나 화면으로 판별하지 않는다(옛 컨테이너가 살아 있어도 화면은 멀쩡히 뜬다).
4. 접속: `/` → 로그인(작업자 이름 + 팀 비밀번호) → 작업공간. 3·4단계(표준화·중장기 전망)는 5번 탭(같은 로그인).
5. 배포 직후 15~20초는 연결이 거부될 수 있다(uvicorn 기동 전). 1분 뒤 연다.

**D. GitHub Pages(소개 사이트)**
- 저장소 Settings → Pages → Source: Deploy from a branch → 폴더를 `/docs`로 지정하려면 패키지의 `docs/`가 저장소 루트 `docs/`여야 한다. 하위 폴더에 올리는 경우엔 `docs/index.html`을 저장소 루트 `docs/`로 복사하거나, Vercel(정적, Root Directory=`2026-09-09-team-package-v0/docs`)을 쓴다.

**E. 비영속 디스크에서 무엇이 남는가**
- 앱 상태는 전부 DB 에 있다 — 원자료·분석 결과·확정·마감·**전망 상태 9종(팩터·정비등급·본사배분 등, 기준연도 축)**·모델·학습데이터. 재배포에도 남는다. (Phase 6 이전에는 전망 앱이 CSV 파일에 상태를 두어 재배포마다 초기화됐다 — 6-5 에서 DB 로 옮기며 사라진 문제.)
- 비영속인 것은 `output/` 의 산출물 파일뿐이고, 요청 시 재생성된다.

### 1.4 운영 점검 항목(무료 배포)
- 슬립 해제 지연을 팀에 공지(첫 접속 30~60초).
- 월 750시간 무료 한도(단일 서비스면 상시 가동 가능).
- Supabase 7일 미접속 정지 → 주 1회 접속 또는 재시작.
- 비밀번호 교체 = Render 환경변수 수정 → 재배포(1~2분). 세션은 SECRET_KEY가 유지되면 남는다(강제 로그아웃은 SECRET_KEY 재생성).

## 2. 보안 구성 요약 (상세: [보안설계.md](보안설계.md))
- **게이트 하나**: 모든 경로가 FastAPI 로그인(HMAC 서명 쿠키, HttpOnly·SameSite=Lax·Secure) 뒤에 있다. 6-8 이전의 엣지 기본인증(`/forecast`)은 전망 앱과 함께 사라졌다.
- **수정 이력**: 로그인 때 받은 **작업자 이름**이 세션에 들어가고 모든 변경 API가 `audit_log`(시각·작업자·경로·상태·요약)에 기록된다. 설정 탭 「변경 이력」에서 조회.
- **비밀은 Git 밖**: `.env`(gitignore)·Render 환경변수·Supabase 대시보드. 코드·문서·이미지에 비밀번호·연결문자열 없음(`.dockerignore`가 `.env`·DB·CSV 차단).
- **실데이터는 Git 밖**: 패키지 `.gitignore`·`.dockerignore` 가 `*.db`·`data_*.csv`·모델 파일·`dist/`(반입용 이미지) 제외.

## 4. 로컬 개발·검증
- 테스트: `cd app && py -m pytest -q` (2026-09-20 기준 **277 passed**, 약 4~5분). `.env`의 `APP_PASSWORD`를 비우면 로그인 없이 개발.
- 로컬 서버: `cd app && py -m uvicorn server:app --port 8010` (프론트는 `cd app/web && npm run build` 먼저). **반드시 `DATABASE_URL=" "`(공백 한 칸)** — 비우면 `.env` 의 운영 PostgreSQL 에 붙는다.
- 배포 구성의 구조 검사(Docker 없이): `tests/test_deploy_config.py`(entrypoint·Dockerfile·compose) · `tests/test_http_hardening.py`(보안 헤더·gzip·캐시) · `tests/test_onprem_package.py`(사내 반입 스크립트).
- 이미지 빌드·실행 검증(Docker 있는 PC): `deploy/onprem/build_image` → `load_and_run` → `check` — [사내이관_가이드.md](사내이관_가이드.md). 개발 PC 에는 Docker 가 없어 **이미지 빌드는 Render 빌드 로그와 `/healthz` 로만 검증**해 왔다(6-8 배포 `449ad38` 에서 보안 헤더·`/assets` 캐시·gzip·`/forecast` 404·`/app/` 301 실측).
