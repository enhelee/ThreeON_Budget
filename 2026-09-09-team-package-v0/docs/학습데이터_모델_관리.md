# 학습데이터 · 모델 관리 방안 (2026-09-09, 사용자 결정 반영)

> 결정: **모델은 DB 레지스트리(메타+BLOB)** · **학습데이터는 DB 테이블 + 확정 워크플로 + 수동 재학습**.
> 구현: `budget_app/src/budget/ml_registry.py`, API `/api/models` `/api/train` `/api/training*`, 설정 탭 「분류 모델 레지스트리 · 학습데이터」, 동기화 `scripts/v2_model_sync.py`.

## 1. 팀에 있는 '학습' 두 가지 — 성격이 다르다

| | budget_app 매칭 학습표(`learned_match`) | v2 투자유형 분류기(scikit-learn) |
|---|---|---|
| 무엇 | (예산과목, 전표텍스트 정규) → 사업명 **규칙표** 10,888건 | TF-IDF(char 2~4그램)+로지스틱회귀 **통계 모델** 3종 |
| 저장 | 이미 DB(`learned_match`, source=수동확정/자동확정, 연도, 시각) | 파일(`type_classifier.joblib`, `project_type_model_*.joblib`) + 학습 CSV — 각자 PC에만 |
| 갱신 | 설정 탭 [AI 학습] 버튼(수동), 사람 확정 > 자동 확정 | v2 화면 [재학습] 버튼 → 파일 덮어씀(버전 없음) |
| 문제 | 없음(이미 DB·이력 있음) | 누가 언제 어떤 데이터로 학습했는지, 어느 파일이 최신인지 알 수 없음. 잘못 학습하면 되돌릴 수 없음 |

→ 이번에 v2 분류기를 budget_app DB의 **레지스트리**로 끌어올렸다. `learned_match`는 기존대로 두되 `audit_log`로 실행 이력이 남는다.

## 2. DB 구조

```
model_registry     id, name, version, trained_at, n_samples, n_classes, metrics_json(cv_accuracy·per_class·confirmed_share),
                   sha256, blob(joblib), active(0/1 — 이름당 1개), snapshot_id, note, created_by
training_example   id, model_name, text, label, source('v2파일반입'|'사람확정'|'자동예측'|'CSV가져오기'),
                   confirmed(0/1), actor, created_at, updated_at, active(0/1)
training_snapshot  id, model_name, created_at, n_examples, sha256, csv(blob), actor   ← 재학습 시점 데이터 고정본
```
모델 이름 3종(v2 파일 대응): `투자유형_전표텍스트`(type_classifier.joblib) · `투자유형_사업명`(project_type_model_major) · `투자유형세부_사업명`(project_type_model_minor). 입력 텍스트는 v2와 같게 맞춘다(사업명 계열은 `"사업명 예산과목"`).

BLOB을 DB에 두는 이유: 모델 크기가 수십 KB~수 MB로 작고, 백업·이전이 DB 하나로 끝나며(Supabase→사내 PG), SHA256으로 무결성이 검증되고, 데이터 스냅샷과 같은 트랜잭션 경계에 있다. 수백 MB 모델이 되면 파일 저장소+메타로 전환(설계상 `blob` 열만 외부 참조로 바꾸면 된다).

## 3. 워크플로

```
① 데이터 들어옴   v2 파일 반입(--push) / CSV 가져오기 / 자동예측 결과(source=자동예측, confirmed=0)
② 사람 확정       설정 탭 또는 API /api/training/confirm → confirmed=1, actor 기록
                  규칙: 사람이 확정한 라벨은 자동값이 절대 덮지 못한다(add_examples). 잘못된 예제는 active=0(삭제 아님)
③ 재학습(수동)    [재학습 → 새 버전] 버튼(관리자, 최소 20건·2유형) → 스냅샷 저장 → 학습 → 새 버전 active
                  CV 정확도·표본수·확정비율이 버전 표에 남음. 자동 재학습·스케줄 없음(검증 없이 바뀌는 것 방지)
④ 검증·롤백       새 버전이 나쁘면 이전 버전 [활성화] 클릭 → 즉시 롤백. 모든 활성화는 audit_log에 기록
⑤ v2 앱 반영      py scripts/v2_model_sync.py --pull → 활성 버전을 v2 파일명으로 내려받음(v2 코드 무수정)
```

## 4. 명령·화면

| 할 일 | 방법 |
|---|---|
| 팀원 PC의 v2 모델·학습 CSV를 DB로 | `py scripts/v2_model_sync.py --push --v2 <v2폴더> --actor 이름` |
| DB 활성 모델을 v2 폴더로 | `py scripts/v2_model_sync.py --pull` |
| 현황 | `py scripts/v2_model_sync.py --status` 또는 설정 탭 |
| 학습 CSV 내보내기/가져오기 | 설정 탭 버튼 · `GET /api/training/export.csv?name=` · `POST /api/training/import?name=` |
| 예제 확정/비활성 | `POST /api/training/confirm {ids,[label]}` · `POST /api/training/deactivate {ids}` |
| 재학습 | 설정 탭 [재학습] · `POST /api/train {name, note}` |
| 롤백 | 설정 탭 [활성화] · `POST /api/models/{id}/activate` |
| 모델 파일 받기 | 설정 탭 [다운로드] · `GET /api/models/{id}/download` |

## 5. 운영 규칙(권장)
- **확정 비율 70% 이상**일 때만 재학습한다(`metrics.confirmed_share`). 자동예측만 쌓인 데이터로 학습하면 오류가 굳는다.
- 재학습 전 `학습 CSV 내보내기`로 검토, 라벨 오류는 확정(라벨 수정)으로 고친다.
- 새 버전 배포 전 v2 「투자유형 예측 테스트」로 표본 100건 이상 육안 검증 → 문제 시 즉시 롤백.
- 분기 1회 스냅샷 CSV를 사내 저장소에 별도 보관(DB 장애 대비).
- `learned_match`(매칭 학습표)는 연도 마감 후 [AI 학습] 1회 원칙 유지(MASTER §3).
