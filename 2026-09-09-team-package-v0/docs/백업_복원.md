# 운영 DB 백업·복원 (2026-10~)

Supabase 무료 플랜이라 대시보드 백업에 기대지 않는다. 사용자 PC 의 작업 스케줄러가 주 1회 백업한다.

## 무엇이 어디에

| 항목 | 값 |
|---|---|
| 스크립트 | `app/scripts/backup_pg.py` (원본은 `read_only` 연결로만 읽음) |
| 원본 | `app/.env` 의 `DATABASE_URL` (운영) |
| 저장 위치 | `문서\ThreeON_DB백업\YYYY-MM-DD_HHMM\` — 표마다 `<표>.csv.gz` + `manifest.json`(행 수·내용 해시·열) |
| 예약 | 작업 스케줄러 `ThreeON_DB_주간백업` — 매주 월 09:00, 꺼져 있었으면 켜진 뒤 바로 · 로그 `문서\ThreeON_DB백업\backup.log` |
| 크기 | 2026-10-18 첫 백업 31표 · 44만 행 · 압축 ~5.5MB |

⚠ 실데이터다. 저장소·공유 폴더에 올리지 않는다. 오래된 백업은 자동으로 지우지 않는다(주 ~6MB).

## 명령 (app 폴더에서)

```
python scripts/backup_pg.py backup            # 지금 백업
python scripts/backup_pg.py check <폴더>       # 파일 행 수 == manifest (DB 접속 없음)
python scripts/backup_pg.py restore <폴더>     # app/.env.migrate 의 TARGET_DATABASE_URL «빈» DB 로
```

- `restore` 는 행이 있는 DB 에는 하지 않는다. 한 트랜잭션으로 넣고 표마다 행 수·내용 해시가 백업과
  같을 때만 확정한다(다르면 되돌림).
- **복원은 아직 실제 PostgreSQL 에서 리허설하지 않았다**(이 PC 에 PG 없음). DB 지역 이전 때 빈
  싱가포르 프로젝트로 한 번 복원해 보는 것으로 검증한다 — [DB_지역이전_절차.md](DB_지역이전_절차.md).

## 확인하는 법

작업 스케줄러 → `ThreeON_DB_주간백업` → 마지막 실행 결과 `0` · 로그 끝줄 `파일 검사 ✅`.
