v0.1 → v0.2 개편. 기존에는 "투자유형 분류"와 "전표–사업 매칭"을 나란한 두 핵심 모듈로 봤다면, 이번 개편으로 전체를 예산 계획 수립 → 예산 실적 분석 → 예산 표준화 → 중장기 예산 예측 4단계 파이프라인으로 다시 짰다. 기존 투자유형 분류 로직은 사라지지 않고 예산 표준화의 한 축으로 흡수된다. 핵심 담당(동료 vs 본인) 구분은 §05에서 다시 정리했다.

01

개요

이 프로그램은 발전플랜트 지사별 유지보수 예산을 4단계로 연결된 파이프라인으로 다룬다. 지사는 매년 예산계획을 엑셀로 작성해 올리고(1단계), 본사는 실적을 업로드해 전표를 사업 단위로 매칭·집계한다(2단계). 그 사이 과년도 실적을 투자유형·정비등급·지사·예산과목 등 여러 축으로 통계 내어 "이 조합이면 보통 이 정도"라는 표준 예산(벤치마크)을 만들고(3단계), 이 표준값에 노후화·물가상승 같은 팩터를 얹어 중장기 예산을 예측한다(4단계).

네 단계 중 2단계의 전표–사업 매칭과 3단계 예산 표준화가 이 시스템에서 가장 판단이 까다로운 핵심 로직이며, 이번 개편부터 동료가 맡는다. 나머지(1·4단계 전체, 2단계의 리포트 화면들, 공통 설정)는 기존처럼 이어서 개발한다.

02

목표와 범위

4단계 개요

STAGE 1

예산 계획 수립

지사별로 수기 작성한 예산계획을 엑셀로 업로드.

STAGE 2

예산 실적 분석

전표를 사업에 매칭해 계획 대비 실적을 만든다.

STAGE 3

예산 표준화

과년도 실적을 여러 축으로 통계 내 표준 예산(벤치마크)을 만든다.

STAGE 4

중장기 예산 예측

표준값에 노후화·물가상승 팩터를 적용해 미래를 예측한다.

목표

  • 지사가 세운 예산계획을, 표준화 단계가 만든 벤치마크와 비교해 볼 수 있게 한다.
  • 전표–사업 매칭을 자동화해 계획 대비 실적을 사업 단위로 만들고, 기존 실적집계표 양식에 채워 넣을 수 있게 한다.
  • 과년도 실적을 투자유형 · 정비등급 · 지사 · 예산과목 등 축으로 표준화해, 반복적으로 쓸 수 있는 기준값을 만든다.
  • 표준값에 노후화·물가상승 등 예측 팩터를 적용해 중장기(다개년) 예산을 예측한다.
  • 사내 분리망에서 완전히 오프라인으로 동작하고, 데이터는 로컬에만 남긴다.

범위 밖 (Non-goals)

  • 정비등급을 이 프로그램이 직접 산정하지 않는다 — 외부에서 만들어진 등급을 파일로 받아 쓰기만 한다(§07, §11).
  • 노후화지수·물가상승률 같은 팩터 값 자체를 통계적으로 추정하는 것은 이번 범위에서는 확정하지 않는다(§11 오픈이슈).
  • 여러 사람이 동시에 같은 데이터를 편집하는 것은 지원하지 않는다 — 로컬 파일 기반 단일 사용자 도구다.
  • ERP에 다시 써넣는(쓰기) 연동은 하지 않는다.
03

사용자

지사 담당자는 매년 자신의 지사 예산계획을 엑셀로 작성해 1단계에 업로드한다. 본사 예산 담당자(1차 사용자)는 실적을 업로드하고, 매칭·분류 결과를 검토·확정하고, 표준화·예측 결과를 리포트로 만들어 배포한다. 관리자/의사결정자(2차 사용자)는 이 리포트와 예측치를 소비한다.

04

구조와 데이터 흐름

실적 업로드는 전표–사업 매칭과 예산 표준화 두 곳에 동시에 입력된다. 매칭 결과는 지사 예산계획과 합쳐져 계획 대비 실적이 되고(1+2단계), 표준화 결과는 지사가 예산을 세울 때 참고 벤치마크가 되는 동시에 중장기 예측의 베이스라인이 된다(3→1, 3→4).

06

전표–사업 매칭 — STAGE 2 핵심

동료 담당

문제

전표 하나하나가 예산계획에 등록된 수십~수백 개 사업명 중 어디에 속하는지 확정해야, 사업별 계획 대비 실적을 만들 수 있다. 고정된 카테고리가 아니라 자유 텍스트(사업명) 매칭이라는 점이 예산 표준화의 분류축들과 다르다.

현재 구현 베이스라인

  • rapidfuzz 문자열 유사도(fuzz.ratio) 기반 매칭. 예산과목(계정과목)이 같은 사업명 후보끼리만 비교해 오매칭과 연산량을 동시에 줄인다.
  • 예산과목당 등록된 사업이 정확히 1개뿐이면 개별 매칭 없이 100% 확신도로 강제 배정한다.
  • 소액(2,000,000원 이하) + 특정 예산과목 조합은 지사별로 자동 묶여 일괄 확정된다. 나머지 저확신 항목은 예산과목별 미분류 묶음으로 제안되거나 사람이 건별로 확정한다.
  • 확신도 임계값 0.6 미만은 화면에서 "검토 필요"로 분리된다.

개선 여지 (자유 설계 영역)

  • 실측 결과 9,000여 건 처리 시 체감 소요 시간이 상당히 길다 — 알고리즘/캐싱 개선이 필요한 지점.
  • 사람이 확정한 매칭 결과를 다음 해 매칭에 학습형으로 재사용하는 것.
  • 사업명 오탈자/표기 차이로 인한 매칭 실패 진단 — 계획 대비 실적 화면의 "매칭 진단"과 연계 개선 여지.
07

예산 표준화 — STAGE 3 핵심 · 신규

동료 담당

문제

같은 지사, 같은 정비등급, 같은 투자유형, 같은 예산과목이라면 해마다 예산이 들쭉날쭉해도 "보통 이 정도"라는 기준이 있을 것이다. 과년도 실적에서 이 기준값(표준 예산)을 뽑아내는 것이 이 단계의 목적이다. 이 값은 1단계에서 지사가 계획을 세울 때 참고 벤치마크가 되고, 4단계 예측의 베이스라인이 된다.

구성 축 4가지

  • 투자유형 — 기존 8종 분류(LTSA · 정기사업 · 노후설비개체 · AX/DX · 운영안정성 제고 · 환경강화 · 교육강화 · 보안강화). 기존 키워드규칙 + TF-IDF/로지스틱회귀 하이브리드 분류 로직(classify.py/hybrid_classify.py/ml_classifier.py)을 그대로 베이스라인으로 재사용할 수 있다 — 이 로직은 더 이상 독립 모듈이 아니라 표준화의 한 축으로 흡수된다.
  • 정비등급 — 신규 축. 설비/자산별 정비등급으로, 이 프로그램이 산정하지 않고 엑셀/파일로 업로드받는 마스터 데이터다(§11 오픈이슈: 스키마 미정).
  • 지사 — 기존 지사유형 매핑(중대형CHP/소형CHP/DH/본사) 재사용.
  • 예산과목 — 기존 계정과목 체계 재사용.

산출물 — 조합별 기준값(벤치마크) 테이블

지사 × 정비등급 × 투자유형 × 예산과목 조합마다 "표준 금액"을 계산해 하나의 테이블로 만든다. 통계 기법(평균/중앙값/최근 N개년 가중 등)과 표본이 부족한 조합의 처리 방식은 동료가 설계하는 영역이다.

  • 통계 기법 선택 — 단순 평균 / 중앙값 / 최근 연도 가중 / 이상치 제거 등.

  • 정비등급 마스터가 없거나 매칭되지 않는 실적 데이터의 처리(§11).

09

나머지 기능 범위

본인 담당

4단계 중 핵심 두 모듈(§06, §07)을 제외한 전체 — 화면, 파이프라인, 신규 UI 포함 — 는 기존 담당자가 계속 개발한다.

비기능 요구사항

  • 완전 오프라인 동작 — 사내 분리망 전제. 표준화·분류 모델 학습·추론 모두 인터넷 연결 없이 로컬에서 수행되어야 한다.
  • 데이터는 로컬에만 — 실적/예산/정비등급/벤치마크 데이터는 외부로 전송되지 않는다. .gitignore로 데이터 파일을 git 추적에서 제외해 둔 원칙을 신규 파일(정비등급 마스터, 벤치마크 산출물)에도 그대로 적용한다.
  • 성능 — 연간 약 9,000건 규모 기준, 매칭·표준화 계산이 화면에서 기다릴 수 있는 시간 내 끝나야 한다(현재 매칭 단계가 상대적으로 느림 — §11).
  • 데이터 정합성 — 연도 데이터 삭제 시 관련 산출물(data_/classified_/matched_)이 함께 정리된다. 벤치마크는 여러 연도를 걸쳐 계산되므로 특정 연도 삭제가 벤치마크에 미치는 영향을 별도로 정의해야 한다.
11

리스크 · 오픈이슈

Open

정비등급 마스터의 출처가 "엑셀/파일 업로드"라는 것만 정해졌다 — 컬럼 스키마, 실적 데이터와의 조인 키(사업장 코드 vs 설비 ID), 갱신 주기는 아직 협의가 필요하다.

Open

중장기 예측의 팩터(노후화지수, 물가상승률) 값을 어디서 가져올지 — 사내 통계 연동인지, 설정 화면에서 수동 입력하는 값인지 정해지지 않았다.

Open

표본이 부족한 조합(지사×정비등급×투자유형×예산과목)에서 벤치마크를 어떻게 계산할지 — 상위 축으로 묶어서라도 값을 낼지, "기준없음"으로 둘지 정책이 필요하다.

Risk

전표–사업 매칭이 9,000여 건 규모에서 체감상 느리다. 알고리즘 병목인지 UI 렌더링 병목인지 먼저 분리해서 봐야 한다.

Risk

매칭 확신도 임계값(0.6)은 경험적으로 정한 값이다. 실 데이터로 정밀도/재현율을 확인하며 튜닝이 필요하다.

Risk

로컬 CSV 파일 기반 저장이라 여러 사람이 동시에 같은 연도 데이터를 편집하면 마지막에 저장한 쪽이 이전 내용을 덮어쓴다.

용어집

정비등급
설비/자산별 정비 상태 등급. 이 프로그램이 산정하지 않고 외부(설비관리시스템 등)에서 만든 값을 파일로 받아 예산 표준화의 한 축으로 쓴다.
표준 예산 / 벤치마크
지사 × 정비등급 × 투자유형 × 예산과목 조합별로 과년도 실적을 통계 내 만든 기준값. 예산 계획 수립 시 참고 자료, 중장기 예측의 베이스라인으로 쓰인다.
예측 팩터
노후화지수, 물가상승률 등 표준 예산에 곱해 미래 예산을 조정하는 값. 팩터 자체의 산출 방식은 §11 오픈이슈.
ZRFM2
실적 조회에 쓰는 ERP 트랜잭션 코드. 이 엑셀 export가 실적 업로드의 원본 데이터다.
LTSA
장기서비스계약(Long-Term Service Agreement) — 투자유형 8종 중 하나.
지사유형
중대형CHP / 소형CHP / DH / 본사 — 사업장이 시간에 따라 소속이 바뀔 수 있어 "적용시작연도" 기준 이력으로 관리한다.
매칭확신도 / 확신도
전표–사업 매칭, 투자유형 분류가 스스로 판단한 신뢰도(0~1). 임계값 미만이면 화면에서 "검토 필요" 항목으로 분리된다.

이 문서는 현재 저장소(개발중/)의 구현 상태와 새로 합의된 4단계 구조를 기준으로 작성된 초안(v0.2)이다. §07 예산 표준화의 산출물 스키마와 §11의 오픈이슈는 리뷰 코멘트로 반영해줄 것.
