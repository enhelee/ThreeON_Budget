## 1. 한 줄 요약
오른쪽 아래 매칭이(«물어보기»)를 누르면 화면 오른쪽에 대화 패널이 열린다. 질문을 **규칙으로 알아듣고**, 숫자는 **앱이 이미 가진 계산(API·모듈)에서만** 가져와 정해 둔 문장 틀에 넣는다. 외부로 나가는 데이터는 없다. 나중에 사내 LLM 이 생기면 «못 알아들은 질문 분류»와 «문장 다듬기»만 맡긴다 — 숫자는 계속 앱이 낸다.

## 2. 왜 이렇게
- 경진대회 전략 문서(10/27): 약점 = «생성형 AI 체감(챗봇·요약) 부족». 경쟁작 = 기획예산처 «AI 예산 어시스턴트»(LLM, ’27).
- 우리 강점은 «숫자가 맞는 것». 챗봇이 숫자를 지어내면 강점이 무너진다 → 숫자는 계산 모듈만.
- 회사 정책: 실금액 + 사업명을 외부 AI 에 넣지 않는다. 최종 운영은 사내망 → 외부 API 없이 돌아가야 한다.

## 3. 범위

| 단계 | 할 수 있는 질문(예) |
|---|---|
| **1차(MVP)** | 사용법 «마감 어떻게 해?» · 이동 «검토 큐 열어줘» · 숫자 «2025 동탄 집행률?», «작년보다 얼마 늘었어?», «초과한 지사 top 5» · 진행 상황 «올해 어디까지 했어?» |
| **2차** | 검토 «남은 검토 몇 건?», «상위 5건» · 전망 «2030 전망 얼마?», «정기점검 표준금액 근거는?» · 설명 «이 사업 왜 초과야?» · 초안 «차이 사유 초안 써 줘» |
| **3차** | 못 알아들은 질문 모음 → 관리자가 규칙 추가(학습 루프) · LLM 어댑터(꺼진 상태로 배포) |

하지 않는 것: 챗봇이 데이터를 **바꾸는** 일(재배정·마감·업로드). 초안은 보여 주기만 하고 저장은 사람이 기존 버튼으로.

## 4. 화면(오른쪽 패널)

```
┌──────────────── 화면 ────────────────┬──── 대화 패널 (폭 380px) ────┐
│                                       │ [매칭이] 무엇을 도와드릴까요?  │
│   (지금 보던 표·차트 그대로)            │  ─────────────────────────── │
│                                       │  나: 2025 동탄 집행률?          │
│                                       │  [매칭이] 동탄지사 2025년       │
│                                       │   집행률 92.4%예요.             │
│                                       │   계획 ○○ · 실적 ○○ (천원)      │
│                                       │   [3+ 상세에서 보기 →]          │
│                                       │   근거: 2025 최신 분석(run 12)  │
│                                       │  ─────────────────────────── │
│                                       │  추천: [작년과 비교] [초과 지사] │
│                                       │  [질문 입력…              ][↵] │
└───────────────────────────────────────┴───────────────────────────────┘
```

- **열기·닫기**: 지금의 «? 도움말» 버튼(매칭이)을 누르면 패널. 기존 «도움말 3줄»은 패널 첫 화면(이 화면 안내 + 추천 질문)으로 옮긴다. Esc·× 로 닫기. 좁은 화면(<1024px)에서는 아래에서 올라오는 시트.
- **답하는 캐릭터**: 주제별로 바뀐다 — 숫자·실적=매칭이(청록), 검토·사유=검토미(산호), 전망·표준금액=예측이(보라), 전표·업로드·사용법=한장이(흰 종이). 답 말풍선 왼쪽에 머리 아이콘.
- **표정**: 답을 만드는 동안 «생각» 표정, 못 알아들으면 «?» 표정, 숫자 답은 기본/웃음.
- **답 카드 모양(고정)**: ① 한두 문장 결론 ② 숫자 표(필요할 때, 최대 5행) ③ «화면에서 보기 →» 버튼(해당 화면·필터로 이동) ④ «근거» 한 줄(어느 연도·어느 분석 실행·어느 계산에서 왔는지). 단위 표기(천원)는 항상.
- **추천 질문 칩**: 화면마다 3~5개(예: 검토 큐 화면 → «남은 금액?», «위험 높음만»). 답 뒤에도 이어지는 질문 칩 2~3개.
- **이 화면 맥락**: «이 지사», «이 사업», «올해»는 지금 화면의 선택(연도·지사·펼친 사업)으로 해석한다. 해석한 값을 답 카드 위에 작게 표시(«동탄지사 · 2025년으로 봤어요»).
- **대화 기록**: 브라우저 탭 안에서만(새로고침하면 지움). 서버에 대화 원문은 저장하지 않는다(6-4 참고).

## 5. 엔진 구조

```
질문 + 맥락(화면·연도·지사·사업)
   │
   ▼
① 정규화      띄어쓰기·조사 제거, 숫자/연도 표기 통일(«25년»→2025, «작년»→연도−1)
   ▼
② 의도 분류   규칙(키워드·패턴 점수) → 의도 1개 + 점수      ← (나중) 점수 낮으면 LLM 분류기
   ▼
③ 칸 채우기   연도·지사·과목·예산구분·사업·N(top) — 사전은 DB 구성(dept_config·item_config·별칭)에서 매번 만든다
   ▼
④ 처리기      의도별 함수가 앱 내부 계산을 **읽기 전용**으로 호출 → facts(숫자 묶음) + 표 + 이동 링크
   ▼
⑤ 문장 만들기 규칙 템플릿                                    ← (나중) LLM 다듬기 + 숫자 검증기
   ▼
답 카드 JSON (character · text · table · links · facts · source · intent · score · engine)
```

### 5-2. 규칙 예 — explain.variance (정해 둔 순서로 «추론처럼» 보이게)
1. 계획 대비: 계획 A · 실적 B · 차이·집행률.
2. 전년 대비: 같은 지사·과목·사업명(정규화) 전년 실적.
3. 큰 전표 3건: 금액·날짜·전표 글자(앱 화면 안에서만 보여 줌).
4. 귀속 근거 분포: 학습·재배정·사업명 유사·총액 기준 비율, 저확신 금액.
5. 등급 신호(정기점검·A급정비 과목): 그해 정비등급이 MI·A 면 «정비등급 영향 가능».
6. 결론 문장 틀: «{사업}은 계획보다 {차이}({집행률}%) 더 썼어요. 큰 전표 3건이 초과분의 {p}%이고, {등급 문장}» — 해당 사실이 없으면 그 문장은 빠진다.

draft.note 는 같은 사실로 «사유 칩»(초과/미달/미시행) + 한 줄 초안을 만들고, 버튼 «사유 칸에 넣기»는 기존 `PUT /api/variance-note` 를 **사람이 누를 때만** 부른다.

### 5-3. 숫자는 앱이 낸다 — 지키는 장치
- 처리기는 서버 안에서 기존 계산 함수를 직접 부른다(HTTP 왕복 없이, 같은 캐시 `viewcache` 사용). 템플릿은 facts 의 값만 꽂고 **새 숫자를 계산하지 않는다**(퍼센트·차이도 처리기가 계산해 facts 에 넣는다).
- 답 카드의 «근거» 줄 = facts 의 출처(연도·분석 실행 id·계산 이름).
- 테스트: 질문 → 처리기 facts 가 같은 연도의 API 응답과 같은지 대조.

## 6. API · 서버

- `POST /api/chat` `{question, context:{view, year, branch?, biz?, base_year?}}` → `{answer:{character, text, table?, links[], facts[], source, intent, score, engine:"rule"}, suggestions[]}`
- `GET /api/chat/suggestions?view=` → 화면별 추천 질문.
- 로그인 필요(다른 API 와 같음). 연도·예산 입력 검증은 기존 미들웨어가 그대로 적용된다.
- **읽기 전용**: 처리기는 쓰기 함수를 import 하지 않는다(테스트로 고정).
- 새 모듈: `src/budget/chat/` — `normalize.py`(정규화·칸 사전) · `intents.py`(규칙 표) · `handlers.py`(의도별) · `templates.py`(문장 틀) · `engine.py`(엔진 교체 지점) · `llm_adapter.py`(3차, 기본 꺼짐).
- 화면: `web/src/components/chat.js`(패널) · `characters.js` 확장(머리 아이콘·표정) · `main.js` 의 `toggle-help` 를 패널 열기로.

### 6-4. 기록·개인정보
- 대화 원문은 서버에 저장하지 않는다. «못 알아들은 질문»만 관리자가 켜면(`CHAT_LOG_UNKNOWN=1`) 질문 글자 + 화면 + 시각을 DB 표 `chat_unknown` 에 남겨 규칙 추가 재료로 쓴다(3차, 설정에서 지우기 가능).
- 감사 로그에는 «질문함(의도)»만 — 숫자를 바꾸지 않으므로 계산 캐시 버전에는 넣지 않는다.

## 7. 나중에 LLM 꽂는 자리 (3차 — 기본 꺼짐)

```
engine.py
  class ChatEngine:  answer(question, context) -> Answer
  RuleEngine        (기본)
  HybridEngine      = RuleEngine + LLM 두 역할만
```
- **역할 ① 분류 보조**: 규칙 점수가 낮을 때만 LLM 에 «의도 목록 중 하나 + 칸(JSON)»을 고르게 한다. 고른 결과는 다시 규칙 처리기로 → 숫자는 여전히 앱.
- **역할 ② 문장 다듬기**: 규칙 답 + facts 를 주고 «말투만» 바꾸게 한다. **숫자 검증기**: LLM 문장에 나온 숫자가 facts 에 없으면 버리고 규칙 문장을 쓴다.
- 연결: OpenAI 호환 주소(`LLM_URL`·`LLM_MODEL`) — 사내 서버(vLLM·Ollama 등)나 회사 승인 클라우드 어느 쪽이든 같은 모양.
- 데이터 경계: `LLM_ONPREM=0`(외부)이면 facts 중 지사·과목 합계만 보내고 사업명·전표 글자·개별 금액은 보내지 않는다. `=1`(사내)일 때만 전부.
- 끄면(`CHAT_ENGINE=rule`) 지금과 똑같이 동작 — LLM 이 없어도 챗봇은 완성품.

## 8. 평가 · 테스트
- **질문 모음(골든셋)** 60개: 의도·칸·기대 숫자 출처. 팀원·재무 담당이 실제로 할 법한 말투로(줄임말·오타 포함). 목표: 의도 정확도 90%↑, 숫자 오답 0.
- 단위 테스트: 정규화(«25년 동탄 손익»→{2025, 동탄지사, 손익}) · 처리기 facts = API 값 · 읽기 전용 · 숫자 검증기.
- 화면 테스트: 패널 열기/닫기·Esc·맥락 해석 표시·«화면에서 보기» 이동.
- 사용 중 지표: 못 알아들은 비율(주 단위) → 규칙 추가 우선순위.
