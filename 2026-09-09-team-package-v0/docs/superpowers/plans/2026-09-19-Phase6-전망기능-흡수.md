# Phase 6 구현 계획 — 전망 기능 흡수 (3·4단계 포팅)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 동료 앱(Streamlit)의 3단계(예산 표준화)·4단계(중장기 전망)를 budget_app 안으로 옮기고, Streamlit·Caddy·supervisord 를 지워 **uvicorn 한 프로세스**로 만든다.

**Architecture:** 포팅 대상 모듈은 이미 순수함수와 파일 IO 가 분리돼 있다. `compute_standard_amounts`·`compute_site_table` 은 DataFrame 을 받아 DataFrame 을 돌려주고, 상태는 전부 `load_*`/`save_*` 쌍 뒤에 CWD 상대경로 CSV 로 숨어 있다. 그래서 포팅은 두 갈래다 — **계산은 거의 그대로 옮기고, 파일 층만 DB 로 바꾼다.** 방금 끝낸 `config_store` 전환(PR #12)과 같은 모양이고, 같은 이유로 필요하다: Render `/data` 는 비영속이라 전망 앱 상태(팩터·고온부품·정비등급)가 배포마다 사라진다.

**Tech Stack:** Python 3.14 · FastAPI · pandas · SQLite/PostgreSQL(dbcore) · Vite + Vanilla JS SPA · pytest

**Spec:** [2026-09-12-통합웹앱-design.md §9](../specs/2026-09-12-통합웹앱-design.md) · 근거 [설계_3-4단계_소요전망_파이프라인.md](../../설계_3-4단계_소요전망_파이프라인.md)

## Global Constraints

- 작업 폴더는 `2026-09-09-team-package-v0/app`. 테스트는 `cd app && py -m pytest -q`.
- **기준선 136 passed** (budget_app). 어떤 태스크도 기존 테스트를 깨뜨린 채 끝내지 않는다.
- **전망 앱 기준선 183 passed** (`cd forecast && py -m pytest tests -q`, 약 65초). 포팅한 계산이 v2 와 같은지는 **이 테스트를 함께 옮겨** 증명한다. 「v2 결과와 일치」의 근거가 말이 아니라 실행 가능한 형태로 남아야 한다.
- SQL 은 `?` 자리표시자로 쓴다 — `dbcore` 가 PostgreSQL 용 `%s` 로 번역한다.
- `INSERT` 는 **컬럼을 명시**한다. 위치 기반 `VALUES(?,?)` 는 컬럼이 느는 순간 조용히 깨진다(Task 1·7 에서 두 번 걸렸다).
- 새 표를 `INSERT OR REPLACE` 로 쓸 거라면 `dbcore.REPLACE_TABLES` 에 등록한다. 아니면 DELETE+INSERT 를 쓴다.
- 프론트 수정 후 반드시 `cd app/web && npm run build`. 브라우저로 확인할 때는 **주소에 `?cb=아무값`** 을 붙이고 **번들 해시가 로컬 빌드와 같은지 먼저 확인**한다 — 옛 `index.html` 을 물고 헛측정한 적이 있다.
- 로컬 검증 서버는 반드시 `DATABASE_URL=" "`(공백 한 칸)으로 띄운다. 비우면 `.env` 의 팀 운영 PostgreSQL 에 붙는다.
- 커밋 메시지는 한국어, 본문에 «왜»를 남긴다. 끝에 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
