## 2. 기능 — 무엇이 생기고 바뀌었나

### 2-1. 검토 큐 (`✓ 검토 큐`, `#/review`) — rev33·34
- **왜**: 분석 뒤 볼 것이 이상 알림 171건·차이 사유 미입력 1,405건·저확신 귀속으로 흩어져 건수만 보였다. 어디서 시작할지 몰랐고 «일이 안 끝났다»로 읽혔다.
- **어떻게**: 사업 한 줄을 검토 단위로 묶고 «검토 금액 × 위험 가중»(과다 귀속·음수 1.5, 저확신 1.2, 차이 1.0)으로 줄 세운다. 같은 돈은 한 번만 센다.
- **처리(1클릭)**: ✓ 이상 없음(승인) · 방향별 사유 칩(초과/미달/미시행) · 추천 재배정(전표 글자가 다른 계획 사업과 분명히 더 닮을 때만 — 유사도 0.75·여유 0.15·설비/연도 충돌 차단) · 사업 골라 옮기기 · 덜 집행된 줄로 가져오기 · 3+ 상세로 이동. 단축키 J·K·A·1~5·E.
- **마감 연도**: 승인·사유는 별도 기록 표(`review_ack`·`variance_note`)에만 저장돼 마감된 숫자를 바꾸지 않는다 → 마감 연도에도 된다. 재배정은 막힌다(423).
- **화면**(rev34 사용자 결정): 큰 머리 카드·파레토 곡선은 빼고 요약 한 줄(남은 건수·금액·처리·위험 높음). 메인 «다음 할 일»도 검토 큐 한 줄.
- 실적 집계의 이상 알림 목록은 검토 큐로 모으고 종류별 건수만(누르면 그 이유로 거른 검토 큐). 큐에 없는 «미매칭 비중»만 줄로 남는다(rev35).

## 6. 개발 메모(다음 사람에게)

- 배포하면 운영 로그인 세션이 풀리기도 한다(rev35 때 풀림, rev36·37 은 유지). Aside 점검 전에 로그인 상태부터 본다. 비밀번호는 사용자가 입력한다.
- PostgreSQL 함정 두 가지: 매개변수가 있는 SQL 에 «%» 를 글자로 쓰면 자리표시자로 읽는다(LIKE 무늬는 매개변수로) · SELECT 목록의 매개변수는 형식을 못 정한다(상수는 글자로). SQLite 테스트로는 안 잡힌다.
- SQLite 는 `JOIN … ON m.run_id = CASE …` 같은 결합에서 실행 색인만 타 행마다 실행 전체를 훑는다(3.3초) — `IN (하위질의)` 로.
- DB 를 API 밖에서 바꾸면 감사 로그를 남겨야 계산 캐시가 갱신된다(아니면 최대 6시간 옛값).
- Aside 는 `/healthz` 요청을 막고, 창이 가려져 있으면 화면 캡처가 시간 초과된다 — 점검은 DOM·Server-Timing 으로.
