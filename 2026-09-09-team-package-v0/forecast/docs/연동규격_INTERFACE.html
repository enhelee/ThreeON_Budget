INTERFACE · 연동 규격서

두 사람이 나눠 만든 부분을 이어 붙이는 약속

서로 코드를 몰라도, 주고받는 파일(CSV)의 칸 이름만 이 문서대로 맞추면 나중에 딱 들어맞습니다. Claude Code로 개발하는 분(양쪽 모두)은 이 문서를 먼저 읽고, 만들 화면이 어떤 파일을 읽고 어떤 파일을 내보내야 하는지를 여기 스펙에 정확히 맞춰 주세요.

2 · 파일로만 연결된다 (큰 그림)

[본인] 실적 업데이트(zrfm2)  ──▶  data_{연도}.csv     ┐
[본인] 예산 계획 업로드       ──▶  budget_{연도}.csv   ┴─▶ [동료] 사업 매칭 · 계획 대비 실적 · 투자유형 분류

[동료] 투자유형 분류 검토     ──▶  classified_{연도}.csv  ──▶ [본인] 집계&대시보드 · 맞춤 리포트 · 예측
[동료] 사업 매칭             ──▶  matched_{연도}.csv     ──▶ [동료] 계획 대비 실적 (동료 내부용)
  • 본인 → 동료로 넘김: data_{연도}.csv, budget_{연도}.csv
  • 동료 → 본인이 받음: classified_{연도}.csv — 이게 안 맞으면 본인의 대시보드·리포트·예측이 안 돌아감
  • matched_{연도}.csv는 동료 화면끼리만 쓰는 내부 파일 (본인은 신경 안 씀)
공통 규칙 (모든 CSV)
  • 인코딩: utf-8-sig (엑셀에서 한글 안 깨지게)
  • 금액 단위: 원(₩). 예산계획 엑셀은 천원 단위지만, budget_{연도}.csv에 저장될 땐 이미 ×1000 해서 원으로 통일됨
  • 파일명의 {연도}는 4자리 정수 (예: data_2025.csv)
  • 빈 값은 비워둠(NaN). 읽을 땐 pd.isna()로 방어

3-4. matched_{연도}.csv — 사업 매칭 결과 〔동료 내부용〕

동료의 사업 매칭 → 계획 대비 실적으로 넘어가는 동료 내부 파일. 본인은 안 읽음. 현행 견본 형식:

= data_{연도}.csv 6칸 + 사업코드 + 사업명 + 매칭확신도(0~1 실수)

4 · 동료가 만들 부분 — 명확한 작업 목록

동료가 Claude Code에게 이 문서를 주고 개발할 때, 만들어야 할 것:

(A) 사업 매칭 화면

  • 입력: data_{연도}.csv(3-1), budget_{연도}.csv(3-2)
  • 하는 일: 전표 한 건씩을 예산계획의 사업명 중 하나에 귀속
  • 출력: matched_{연도}.csv(3-4)
  • 내부 알고리즘 자유 (budget_app의 예산과목×처지사 2-키 그룹 방식 권장 — 총액 유실 0)

(B) 계획 대비 실적 화면

  • 입력: budget_{연도}.csv(3-2), matched_{연도}.csv(3-4)
  • 하는 일: 사업명 기준 연예산(A) vs 실적(B) 대조, 손익/자본 양식 채워 엑셀 산출
  • 출력: 다운로드용 엑셀 (형식 자유)

(C) 투자유형 분류 검토 화면 ⚠️ §6 먼저 확인

  • 입력: data_{연도}.csv(3-1)
  • 하는 일: 전표헤더텍스트를 보고 투자유형 8종 중 하나로 분류, 사람이 검토·확정
  • 출력: classified_{연도}.csv(3-3) — 본인 화면들이 이걸 먹고 삽니다. 3-3 스펙 정확히 지킬 것.

5 · 본인이 만들 부분 (이미 대부분 완료)

  • 실적 업데이트(zrfm2) → data_{연도}.csv 생성 완료
  • 예산 계획 업로드 → budget_{연도}.csv 생성 완료
  • 집계&대시보드 · 맞춤 리포트 · 예측 모델 → classified_{연도}.csv 소비 완료
  • 설정(매핑 관리·모델 관리), 예산 표준화(자리표시자), 전체 메뉴/라우팅 완료

현재 개발중/에는 동료가 만들 3개 화면의 임시 견본이 들어 있음. ①전체 앱을 지금 테스트 가능하게 하고 ②동료에게 "출력이 이렇게 나와야 한다"를 실물로 보여주는 명세 역할. 동료 완성본이 나오면 교체.

6 · ⚠️ 지금 서로 확인해야 할 것 (착수 전 합의)

  1. 투자유형 분류 검토는 누가? — 본인은 "동료가 만든다"로 알고 있으나, 동료 PRD(PRD_V1)에는 투자유형 분류가 2단계 작업으로 안 들어있고 3단계(표준화)로 미뤄져 있음. 동료가 이 화면을 만들고 classified_{연도}.csv(3-3)를 출력하는 게 맞는지 확정 필요. (안 그러면 본인의 대시보드·리포트·예측이 재료를 못 받음)
  2. budget_app을 본인 앱에 합칠지, 따로 둘지 — 최종적으로 팀원이 프로그램 하나만 열게 하려면 합치는 게 목표. 당장은 각자 만들고 이 파일 규격만 지키면 나중에 합쳐짐.
  3. 부서코드 매칭 규칙 — 실적의 손익센터(4자리)와 예산의 부서코드(6~7자리)는 앞 3자리가 같으면 같은 사업소로 취급. (본인 쪽 mapping_config.get_site_display_name에 이미 구현 — 동료도 처지사 정규화 시 같은 규칙 쓰면 결과 일치)

7 · 개발 환경 (양쪽 공통)

  • Python 3.13 · Streamlit · pandas · openpyxl · rapidfuzz · scikit-learn (requirements.txt 참고)
  • 완전 오프라인(사내 분리망) — 인터넷 필요한 라이브러리 금지
  • 실데이터 CSV/엑셀은 git에 올리지 말 것 (.gitignore 등록됨)
  • 금액은 원(₩) 단위, CSV 인코딩은 utf-8-sig
