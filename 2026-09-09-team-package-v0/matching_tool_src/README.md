# 사업매칭 중간 점검본

2026-09-08, 기준 main `78404ea6ee5aee240b1685602eff1360ea1aa148`.
독립 매칭 작업본과 통합 앱의 연결 모듈이다. 후속 변경으로 예측 Streamlit에 사업 실적 연결 메뉴와 표준화·예측 입력 선택을 추가했다. 저장소 루트의 실행방법.md 및 run_budget.py를 사용한다. 원본 전표와 기존 분류 CSV는 보존한다.

## 바로 실행

1. `예산실적정리.html`을 다운로드해 브라우저에서 연다. 서버·설치·인터넷 연결 없이 실행된다.
2. ERP RAW, 손익/자본 집계표를 선택한다. 집계표 사업명이 후보이며 최종 실적 대조 모드는 기준 실적이 있는 과거 자료용이다.
3. 담당자 보정 Excel 또는 로컬 보정 JSON을 선택한다. 이 공개 점검본의 내장 보정은 비어 있다. 기존 확인사항의 정확한 재현에는 담당자가 별도 보관한 JSON을 사용한다.
4. 양식2·3, 검토목록, 묶음배정, 예비품 날짜 내역을 내려받는다.
5. `팀 점검용 결과 JSON 다운로드` 후 아래 Python 화면에서 같은 결과를 검토할 수 있다.

```sh
# 저장소 루트에서 실행, 기존 팀 Streamlit 환경 사용
streamlit run checkpoints/2026-09-08-codex/review_app.py
```

Python 화면은 결과 표를 읽기만 한다. 기존 `data_*.csv`, `matched_*.csv`, `classified_*.csv`를 덮어쓰지 않는다. 이 독립 검토 화면은 읽기 전용이다. 실제 표준화·예측 연결은 통합 앱의 「사업 실적 연결」 메뉴에서 확인 후 저장한다. 매칭 엔진은 JS를 유지하며 Python에서는 배정 결과를 원 단위로 검증·수신한다.

## 이번에 포함한 기능

- 지사×과목 범위에서 사업명/금액 대조, 후보 중복·불명확한 합산은 검토.
- 예비품·저장품·고온부품은 전기일별 전체 양수/음수 순액을 먼저 합산하고 원천행 추적.
- 보정의 원천금액·참조 사업·계약 묶음을 검증. 확인된 복수 사업 계약과 건별 허용차이 지원.
- 원천합계·기준합계·잔차·제외·검토를 각각 유지. 결과 JSON의 금액은 열 표시대로 천원.
- 실제 사업/금액 보정 데이터는 코드와 분리. `private/`는 Git 제외. 민감한 결과 JSON/엑셀도 커밋하지 않는다.

그룹으로 확인한 계약은 개별 원전표의 사업별 정산까지 확인된 것으로 취급하지 않는다. 배정 합계는 순액과 같고 잔차가 있으면 최대금액 사업행에 반영해 표시한다. 특정 연도의 실제 이름은 보정 자료이며 일반 판정 규칙이 아니다.

## 팀 앱과의 통합 경계

저장소에는 초기 루트 Streamlit, `2026-09-08_예산예측프로그램`의 예측 앱, `docs/superpowers/예산 실적 집계`의 FastAPI 앱이 공존한다. 사업 실적 연결 메뉴가 그룹·사업행 ID, 금액 합계, 연도를 검증하고 표준화·예측 입력으로 연결한다. 나머지 기존 매칭 경로의 엔진 통일은 후속 과제다.

먼저 수정할 기존 경로:

- 예측 앱 `project_matching.py`: 후보 마스터가 지사를 보존하도록 변경.
- `plan_vs_actual.py`: 사업명만으로 합치지 말고 지사×과목×사업행 키로 집계.
- `validate_upload.py`: 타 지사/과목 상쇄와 예비품 원문 덮어쓰기를 방지.
- `classification_review_page.py`: 사업 매칭과 투자유형 분류 결과의 연결 ID 보존.
- FastAPI `matching.py`: 문서번호 묶음/불확실한 강제 귀속과 이 엔진의 규칙을 통일.
- FastAPI CSV의 `매칭사업명`/`금액원`과 Streamlit `사업명`/`금액`을 명시적으로 변환. 날짜·사업장·원천행도 전달.

원전표 전체금액을 복수 사업마다 반복 복제하지 않는다. 원전표, 계약/날짜 그룹, 사업별 배정, 제외/검토는 각각 관리해야 한다. 기준실적을 입력으로 맞춘 포착률은 미지의 다른 연도에 대한 예측 정확도가 아니다.
