01

문제 / 수치화

10년 이상의 전표 데이터는 확보되어 있으나, 정비 예산 수립이 담당자의 경험치에 의존하고 있어 근거를 설명하기 어렵고 반복 작업 시간이 크다.

구분내용
데이터 소스ERP → Excel export → 정형 양식 업로드
데이터 범위10년 이상, 개별 전표 단위, 연간 집계
현재 편차연간 예산 대비 실적 편차 10% 이내 (양호)
핵심 원인정비 계획 자체가 담당자 경험치에 의존 → 근거·표준화 부재
현재 영향큰 사고는 없으나 비효율적 (반복 작업, 설명 근거 부족)
기존 수작업 규모유지보수부서 약 400명이 2주간 작업 + 예산주관담당자가 약 3개월간 취합·조정 (현재까지의 방식)
지금까지는 매년 유지보수부서 약 400명이 2주에 걸쳐 실적/계획 자료를 작성하고, 예산주관담당자가 이를 약 3개월간 취합·조정해 최종 예산안을 만들어왔음. 이 소요 인력과 시간을 줄이는 것이 핵심 목표 중 하나.

03

화면 설계

6단계 개발 로드맵 중 1~2단계는 프로토타입 완성, 나머지는 설계 예정입니다.

단계화면핵심 기능상태
1데이터 업로드 & 검증연도별 업로드, 5칸 롤링 현황판(그룹+최근4년), 행 단위 오류 검출(치명적/경고)완료
2투자유형 분류 검토규칙기반→학습모델 자동전환, 확신도순 정렬, 모델 관리(재학습/초기화/내보내기)완료
3집계 & 대시보드지사×과목×유형 집계, 예산 vs 실적 시각화예정
4예측 모델유형별 회귀/추세 예측예정
5시뮬레이션물가상승률·노후화·돌발정비 팩터 조정예정
6전체 조립단일 웹앱으로 연결예정
1·2단계 화면은 목업 → 실제 Streamlit 코드로 구현하고, 더미 데이터로 전체 시나리오(10년치 업로드, 오류 검출, 분류, 재학습)를 실제 실행하여 검증 완료.

08

필요한 개념 (개발자용 용어 정리)

지도학습 (Supervised Learning)
사람이 정답(라벨)을 알려준 데이터로 모델을 학습시키는 방식. 여기서는 "이 텍스트는 LTSA다"처럼 확정된 분류를 학습 데이터로 사용.
TF-IDF
텍스트를 숫자로 변환하는 방법 중 하나. 문서에서 자주 나오지만 다른 문서엔 잘 안 나오는 단어에 가중치를 준다. 여기서는 전표헤더텍스트를 모델이 이해할 수 있는 형태로 바꾸는 데 사용.
로지스틱 회귀 (Logistic Regression)
여러 카테고리 중 하나로 분류하는 데 쓰는 기본적인 머신러닝 알고리즘. 가볍고 빠르며 사내망처럼 제한된 환경에서도 잘 동작함.
교차검증 (Cross Validation)
가진 데이터를 여러 조각으로 나눠 서로 다른 조각으로 학습/평가를 반복해 모델의 신뢰도(정확도)를 추정하는 방법.
확신도 (Confidence)
모델이 예측한 결과를 얼마나 확신하는지 나타내는 수치(0~100%). 낮으면 사람이 직접 검토해야 할 대상.
규칙기반 분류 (Rule-based Classification)
키워드 사전을 만들어 "이 단어가 있으면 이 유형" 식으로 분류하는 방식. 학습 데이터가 부족할 때 임시로 사용.
세션 상태 (Session State)
Streamlit 화면에서 사용자가 클릭하거나 입력한 값을 화면이 다시 그려져도 기억하게 해주는 저장 공간.
