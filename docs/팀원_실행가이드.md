# 팀원 실행 가이드 — `2026-09-09-team-package-v0` (2026-09-09)

## 1. 세 가지 실행 방법

| 방법 | 언제 | 명령 |
|---|---|---|
| **A. 각자 PC에서 실행** | 지금 바로, 서버 없이 | Windows: `실행_1_예산실적집계(budget_app).bat` · `실행_2_예산예측프로그램(v2).bat` / Mac: `bash 실행_mac.sh` |
| **B. 공개 URL 접속** | 팀 검토 기간 | Render 주소 → `/app/`(작업자 이름+팀 비밀번호) · `/forecast`(사용자 team+팀 비밀번호). 첫 접속 30~60초 대기 |
| **C. 사내 서버** | 최종 | `docker compose -f deploy/docker-compose.yml up -d --build` (배포가이드 §3) |

### A. 각자 PC
1. Python 3.12~3.14 설치(PATH 체크).
2. 처음 한 번 `budget_app/.env` 만들기: `deploy/.env.example`을 복사해 `APP_PASSWORD`, `SECRET_KEY`를 채운다. 비우면 로그인 없이 열린다(개인 PC 전용).
3. `실행_1_…bat` → http://localhost:8010 · `실행_2_…bat` → http://127.0.0.1:8501 (bat이 `pip install -r requirements.txt`를 먼저 실행).
4. 데이터는 각자 PC에만 생긴다: `budget_app/data/budget.db`, `forecast_app/*.csv`·`checkpoint_data/`. **Git에 올리지 않는다**(gitignore 되어 있음).

## 2. 일상 작업 순서
1. **budget_app** — 연도 선택 → 계획본(양식1(월별))·zrfm2 업로드 → `분석 실행` → 상세에서 재배정·✎수정·삭제·추가 → `분석 반영 (N)` → 설정 탭 `AI 학습` → 필요 시 `연도 마감`.
2. **팀 연계** — 「4 통계·내보내기 → 팀 연계 → 결과 JSON」 다운로드.
3. **forecast_app(v2)** — 「예산 실적 집계 → 사업 실적 연결」에 JSON 업로드 → `배정분을 표준화·중장기 예산에 연결` → 「예산 표준화」·「중장기 예산」에서 「연결한 사업 실적」 선택 → 계산·엑셀 내보내기.
4. **모델** — v2 「투자유형 분류 검토」에서 확정한 학습 CSV를 budget_app 설정 탭 「학습 CSV 가져오기」로 DB에 쌓고, 관리자가 [재학습] → v2 폴더로 `py scripts/v2_model_sync.py --pull`.

## 3. 로그인·이력
- 로그인 때 입력한 **작업자 이름**이 모든 변경(재배정·수정·삭제·추가·분석·학습·마감)에 기록된다 → 설정 탭 「변경 이력」. 실명(또는 팀 내 고정 별명)을 쓴다.
- 비밀번호를 잊으면 관리자가 `.env`(로컬)/Render 환경변수에서 확인·교체.

## 4. 자주 묻는 것
- **"분석 후 첫 다운로드가 느려요"** — 산출물은 분석 때 만들지 않고 첫 다운로드에서 생성(20~30초). 두 번째부터는 즉시.
- **"v2에 올린 JSON이 거부돼요"** — 연도가 다르거나 여러 연도가 섞인 파일. budget_app에서 해당 연도로 다시 내보내기. 미배정은 0이어야 정상.
- **"v2 표준화에 금액이 빠져요"** — budget_app에서 과목·지사를 선택 해제한 상태로 내보냈을 때 미반영분이 '제외'로 간다. 구성을 전체 선택 후 다시 내보내기.
- **"Render 주소가 안 열려요"** — 슬립 해제 중(최대 1분) 또는 무료 한도. `/healthz`로 확인.
- **"Python 3.12가 없다고 해요"** — v2 원본 `실행_Windows.bat`은 3.12 전용. 패키지의 `실행_2_…bat`은 현재 PC Python을 쓴다.
