## 2. 파일로만 연결된다 (큰 그림)

```
🟦 본인: 실적 업데이트(zrfm2)   ──▶  data_{연도}.csv     ┐
🟦 본인: 예산 계획 업로드        ──▶  budget_{연도}.csv   ┴─▶ 🟧 동료: 사업 매칭 · 계획 대비 실적 · 투자유형 분류

🟧 동료: 투자유형 분류 검토      ──▶  classified_{연도}.csv  ──▶ 🟦 본인: 집계&대시보드 · 맞춤 리포트 · 예측
🟧 동료: 사업 매칭              ──▶  matched_{연도}.csv     ──▶ 🟧 동료: 계획 대비 실적 (동료 내부용)
```

- **본인 → 동료로 넘김**: `data_{연도}.csv`, `budget_{연도}.csv`
- **동료 → 본인이 받음**: `classified_{연도}.csv` ← **이게 안 맞으면 본인의 대시보드·리포트·예측이 안 돌아감**
- `matched_{연도}.csv`는 동료 화면끼리만 쓰는 내부 파일 (본인은 신경 안 씀)

**공통 규칙** (모든 CSV)
- 인코딩: `utf-8-sig` (엑셀에서 한글 안 깨지게)
- 금액 단위: **원(₩)**. (예산계획 엑셀은 천원 단위지만, `budget_{연도}.csv`에 저장될 땐 이미 ×1000 해서 원 단위로 통일돼 있음)
- 파일명의 `{연도}`는 4자리 정수 (예: `data_2025.csv`)
- 빈 값은 비워둠(NaN). 코드에서 읽을 땐 `pd.isna()`로 방어할 것.

## 3. 파일별 상세 규격

### 3-1. `data_{연도}.csv` — 실적 원자료 〔본인이 만듦 → 동료가 읽음〕

실적 엑셀(ZRFM2)을 검증·정제한 결과. **동료의 사업 매칭·투자유형 분류의 입력.**

| 칸 이름 | 뜻 | 예시 |
|---|---|---|
| `거래처명` | 협력업체/거래처 | (주)○○기공 |
| `사업장` | 손익센터 코드(4자리) 또는 이름 | `3070.0` |
| `전기일` | 자금 집행일 (날짜) | `2025-03-14` |
| `전표헤더텍스트` | 전표 자유 텍스트 (매칭·분류의 핵심 단서) | `동탄 3호기 정기점검 부품구매` |
| `금액` | 실적 금액(원) | `25947300` |
| `계정과목` | 예산과목 (정식 명칭으로 정규화됨) | `수선유지비-열원보완및개선` |

> 정제 완료 상태로 넘어감: 합계행 제거, KSV5 제외, 역분개 상쇄, 인지세 합산 등은 이미 처리됨. 동료는 이 파일을 **있는 그대로 신뢰**하면 됨.

### 3-2. `budget_{연도}.csv` — 예산 계획 〔본인이 만듦 → 동료가 읽음〕

예산계획 엑셀(양식1·예산코드·부서코드)을 파싱한 결과. **동료의 사업 매칭 마스터·계획 대비 실적의 입력.**

핵심으로 쓰는 칸(이 이름 그대로 유지 필수):

| 칸 이름 | 뜻 | 비고 |
|---|---|---|
| `사업명` | 사업 이름 (매칭 대상) | 매칭의 정답 후보 |
| `예산과목` | 예산과목 (정식 명칭으로 정규화됨) | `data`의 `계정과목`과 대조 |
| `연예산 합계` | 연예산(원) | 이미 천원→원 환산됨 |
| `예산귀속 \n부서코드` | 부서코드(6~7자리) | 줄바꿈(`\n`)이 칸 이름에 포함됨 — 주의 |
| `예산귀속\n부서명(처.지사)` | 처·지사 이름 | 종합표 24개 지사 기준값 |
| `예산코드` | 계정코드 | |
| `속성`, `주관부서명`, `본부`, 월별(`1월`~`12월`) 등 | 원본 그대로 통과 | 매칭엔 불필요 |

> ⚠️ 부서/부서명 칸 이름에 **줄바꿈 문자(`\n`)가 들어있음**. 코드에서 참조할 때 정확히 `"예산귀속\n부서명(처.지사)"`로 써야 함.

## 4. 동료가 만들 부분 — 명확한 작업 목록

동료가 Claude Code에게 이 문서를 주고 개발할 때, **만들어야 할 것**은 다음과 같습니다:

### (A) 사업 매칭 화면
- **입력**: `data_{연도}.csv`(3-1), `budget_{연도}.csv`(3-2)
- **하는 일**: 전표 한 건 한 건을 예산계획의 `사업명` 중 하나에 귀속
- **출력**: `matched_{연도}.csv`(3-4)
- 내부 알고리즘은 자유 (budget_app의 예산과목×처지사 2-키 그룹 방식 권장 — 총액 유실 0)

### (B) 계획 대비 실적 화면
- **입력**: `budget_{연도}.csv`(3-2), `matched_{연도}.csv`(3-4)
- **하는 일**: 사업명 기준으로 연예산(A) vs 실적(B) 대조, 손익/자본 양식 채워 엑셀 산출
- **출력**: 다운로드용 엑셀(형식 자유)

### (C) 투자유형 분류 검토 화면  ⚠️ §6 먼저 확인
- **입력**: `data_{연도}.csv`(3-1)
- **하는 일**: `전표헤더텍스트`를 보고 투자유형 8종 중 하나로 분류, 사람이 검토·확정
- **출력**: `classified_{연도}.csv`(3-3) ← **본인 화면들이 이걸 먹고 삽니다. 3-3 스펙 정확히 지킬 것.**

## 6. ⚠️ 지금 서로 확인해야 할 것 (착수 전 합의)

1. **투자유형 분류 검토는 누가?** — 본인은 "동료가 만든다"로 알고 있으나, 동료 PRD(PRD_V1)에는 투자유형 분류가 2단계 작업으로 안 들어있고 3단계(표준화)로 미뤄져 있음. **동료가 이 화면을 만들고 `classified_{연도}.csv`(3-3)를 출력하는 게 맞는지 확정 필요.** (안 그러면 본인의 대시보드·리포트·예측이 재료를 못 받음)
2. **budget_app을 본인 앱에 합칠지, 따로 둘지** — 최종적으로 팀원이 프로그램 하나만 열게 하려면 합치는 게 목표. 당장은 각자 만들고 이 파일 규격만 지키면 나중에 합쳐짐.
3. **부서코드 매칭 규칙** — 실적의 손익센터(4자리)와 예산의 부서코드(6~7자리)는 **앞 3자리가 같으면 같은 사업소**로 취급. (본인 쪽 `mapping_config.get_site_display_name`에 이미 구현됨 — 동료도 처지사 정규화 시 같은 규칙 쓰면 결과가 일치)

## 8. `팀연계_{연도}_사업실적연결.json` — 사업 실적 연결 결과 〔budget_app이 만듦 → v2 앱이 읽음〕 ★3·4단계 입구★ (2026-09-08 추가)

v2 앱 「예산 실적 집계 → 사업 실적 연결」에 올리는 파일. 검증 코드는 v2 `checkpoint_actuals.prepare_result()`,
생성 코드는 budget_app `src/budget/spec_io.build_team_result_json()`. **이 파일이 맞지 않으면 v2가 업로드를 거부한다**(총액 검증 포함).

### 8-1. 상위 키
| 키 | 값 | 비고 |
|---|---|---|
| `schemaVersion` | `1` | 고정 |
| `amountUnit` | `"KRW_THOUSAND"` | 표의 금액은 **천원**(소수 허용). `sourceTotals.amountWon`만 **원** |
| `amountMatching` | `true` | 최종 실적금액 대조 모드 |
| `sourceYears` | `[연도]` | **단일 연도** 정수 배열. 업로드 시 선택 연도와 같아야 함 |
| `sourceTotals` | `[{ledger, org, account, amountWon}]` | (원장·지사·과목)별 원천 순액(원). 배정·제외한 모든 (원장·지사·과목)이 여기 있어야 함 |
| `reconciliation` | `{groups, details, exclusions, corrections, differences, spareDates, spareSources}` | 각각 **첫 행이 헤더**인 2차원 배열 |
| `generator`, `summary`, `generatedAt` | budget_app 부가 정보 | v2는 읽지 않음(무시) |

### 8-2. 표 헤더(정확히 이 문자열·순서)
- `groups`(13열): `묶음ID, 원장, 지사, 예산과목, 처리방법, 전표 합계(천원), 사업 실적 합계(천원), 단수차이(천원), 전표항목수, 사업수, 대상 사업명, 전표텍스트, 참조전표번호`
- `details`(8열): `묶음ID, 원장, 지사, 예산과목, 집계표 원본행, 사업명, 기준 실적(천원), 반영 실적(천원)`
- `exclusions`(8열): `원장, 지사, 예산과목, 전표텍스트, 제외 금액(천원), 담당자 제외 사유, 보정ID, 참조전표번호`
- `corrections`·`differences`·`spareDates`·`spareSources`: 헤더 행만(v2 검토 화면 호환용)

### 8-3. v2가 검사하는 규칙 (하나라도 어기면 거부)
1. `원장` ∈ {손익, 자본}. `지사`·`예산과목`·`사업명`·`묶음ID` 비어 있으면 안 됨.
2. 묶음마다 `details`의 `반영 실적(천원)` 합 × 1000 == `groups`의 `전표 합계(천원)` × 1000 (원 단위 정확 일치, 소수 오차 0.01원 이내).
3. `집계표 원본행`은 1 이상 정수. (원장·지사·과목·원본행) 조합 중복 금지.
4. `details`의 지사·과목이 소속 묶음과 같아야 함.
5. 배정·제외한 (원장·지사·과목)이 `sourceTotals`에 있어야 함. `미배정순액 = 원천 − 연결 − 제외`가 화면에 표시됨.

### 8-4. budget_app 매핑 규칙
| 항목 | 값 |
|---|---|
| 묶음 | (원장 × 처지사정규 × 과목정규 × 귀속 사업). 계획집행은 계획행 `_row`로, 신규는 `[신규] ` 라벨로 묶음. 묶음ID `P000001`(손익)/`C000001`(자본) |
| `집계표 원본행` | 계획집행 = 양식1(월별) 계획행 번호, 신규 = `2,000,000 + n` 합성 번호 |
| `사업명` | `매칭사업명`에서 `[신규] ` 접두 제거 |
| `exclusions` | 구분 **미반영** 전표(선택 해제 과목·지사 / 미분류 / 미매핑). 지사 미확인 시 ERP 원문 지사명 |
| 제외 대상 | 구분 `''`(타예산)·`제외(합계행/타연도)` — 타예산은 상대 원장에서 집계 |
| 불변식 | Σ`sourceTotals` = Σ배정 + Σ제외 → **미배정 0**. 실측 2025: 손익 98,554,800,525원 · 자본 49,709,177,979원 |

### 8-5. 함께 나오는 CSV(연도 단일 파일, 원 단위)
