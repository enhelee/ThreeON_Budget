01 · 개요

발전플랜트 지사별 유지보수 예산을 4단계 파이프라인으로 다룬다. 지사가 예산계획을 엑셀로 올리고(1단계), 본사가 ERP 실적을 업로드해 전표를 사업 단위로 매칭·집계한다(2단계). 과년도 실적을 여러 축으로 통계 내어 표준 예산(벤치마크)을 만들고(3단계), 여기에 노후화·물가상승 팩터를 얹어 중장기 예산을 예측한다(4단계).

v1.0 시점 구현 상태: 1단계(예산 계획 수립)와 2단계(예산 실적 분석·전표–사업 매칭)는 budget_app에 구현·검증 완료. 3·4단계는 설계 단계.

02 · 목표와 범위

단계내용상태

STAGE 3 · 예산 표준화과년도 실적을 투자유형·정비등급·지사·예산과목 축으로 통계 → 벤치마크설계
STAGE 4 · 중장기 예산 예측벤치마크에 노후화·물가상승 팩터 적용 → 다개년 예측설계

범위 밖 (Non-goals)

  • 정비등급을 직접 산정하지 않는다 — 외부 파일로 받아 쓴다(§07, §11).
  • 노후화지수·물가상승률 팩터 값 자체의 통계 추정은 이번 범위 밖(§11).
  • 동시 편집 미지원 — 로컬 파일 기반 단일 사용자 도구.
  • ERP 역방향 쓰기(연동) 없음.

03 · 사용자

지사 담당자는 매년 지사 예산계획을 엑셀로 1단계에 올린다. 본사 예산 담당자(1차 사용자)는 실적을 업로드하고 매칭·분류 결과를 검토·확정하며, 표준화·예측 리포트를 배포한다. 관리자/의사결정자(2차 사용자)는 리포트·예측치를 소비한다.

04 · 구조와 데이터 흐름

실적 업로드(zrfm2)는 전표–사업 매칭과 예산 표준화 두 곳에 입력된다. 매칭 결과는 지사 예산계획과 합쳐져 계획 대비 실적이 되고, 표준화 결과는 지사 예산 수립의 참고 벤치마크이자 중장기 예측의 베이스라인이 된다.

[zrfm2 실적] ──┤

06 · 전표–사업 매칭 STAGE 2 핵심 구현완료

문제

ERP 전표(zrfm2) 하나하나가 예산계획에 등록된 수십~수백 개 사업 중 어디에 속하는지 확정해야 사업별 계획 대비 실적을 만들 수 있다. 계획 사업명과 ERP 전표 텍스트의 표기 차이가 매우 크다는 것이 이 단계의 최대 난점이다(실데이터에서 사업명만으로는 유사도 80% 기준 매칭이 전체 실적의 약 1.5%에 불과).

핵심 설계 원칙(v1.0): 사업명 유사도는 보조 신호로만 쓰고, 집계의 뼈대는 (예산과목 × 처지사) 2-키 그룹으로 삼는다. 이로써 실적 총액이 ERP 전체와 정확히 일치(유실 0)하는 것을 보장하면서, 사업명 매칭 품질과 무관하게 지사별 종합표가 완전해진다.

매칭 우선순위 (요구사항)

순위키구현
1순위예산과목ERP 계정코드(B열)→예산코드 마스터→표준명, 계획본은 연도별 개명 별칭으로 정규화(계정코드 동일 개명 흡수: 24년 열원보완개선및기타 ↔ 25년 열원보완및개선). 사용자 예산과목 구성에 없으면 결측(미분류)로 보고.
2순위처지사ERP 지사명(I열)을 계획 처지사로 정규화(별칭 override → 괄호/공백 제거 → 접두 → J열 부서명 참조 → rapidfuzz). 실패 시 검토리포트 보고.
3순위사업명같은 (과목×처지사) 그룹 내에서 rapidfuzz.WRatio로 최고 유사 계획행에 귀속(tie-break). 유사도는 매칭확신도(0~1)로 산출.

분류 체계 (v1.0 확정)

구분정의산출
계획집행계획O · 실적O — 계획행에 ERP 전표가 귀속됨실적금액 = 귀속 전표 합, 매칭확신도(평균)
미시행계획O · 실적X — 귀속 전표 없음실적 0, 연빨강 강조

구성 선택 · 미반영 (v1.0 rev2)

실적 분석 탭에도 계획 탭과 동일 config를 공유하는 지사 구성·예산과목 구성 편집기를 두어, 선택(포함)된 과목·지사만 실적본(양식1·종합표)에 반영한다. 포함 해제·미분류·미매핑 처지사 전표는 zrfm2_V1의 반영구분='미반영'으로 표기해 보존한다(양식1엔 미표시). 과목구성의 실적반영:false(건설공사 3과목)는 계획본엔 유지, 실적에서만 제외. 정합식: 실적 종합표 총액 + 미반영 + 타예산 = 이번 예산 ERP 전체(유실 0).

검증 사례 ① — 경상정비 "지사 귀속" 자동 정합 교차검증

수기 취합본 (양식2)…취합자료_R1과 자동 산출을 예산과목별로 대조한 결과, 손익 5/6·자본 8/11 과목이 오차 0.05~2%로 일치했다. 유일한 큰 차이였던 수선유지비-열원경상정비는 분석 끝에 실제로는 같은 값임이 확인됐다.

  • 취합본은 본사 발주 경상정비공사 6건(연예산 41.6억천원 — 중대형CHP 34.8M, DH 3.3M 등)의 실적 칸을 숫자가 아니라 "지사 귀속" 텍스트로 남겨두었다(실제 집행은 각 지사로 귀속되므로 본사 취합 시 수기 기입 불가).
  • 본 프로그램은 zrfm2의 지사별 전표를 자동 매칭해 이 경상정비 실적을 39,368,679천원으로 정량화했다.
  • 수기 취합본 _R1이 이후 이 칸을 지사별 실수치로 채웠고, 그 값이 우리 자동집계와 정확히 일치(39,368,679 = 39,368,679)함이 재검증됐다 — 우리가 먼저 자동으로 채운 값이 옳았음이 사후 확증됨.
  • 손익 총액 정합: 자동 98,554,801 vs 참조 _R1 98,345,148 = +209,651(0.21%). 차이는 건물/구축물 본사귀속 완전포착 +204,889(참조 0)뿐, 나머지 5과목 ±5천원 반올림.

시사점: 수기 취합이 사람 손으로 채우지 못해 "지사 귀속"으로 비워둔 칸을, 전표–사업 매칭이 자동으로 정량 완성한다. 자동화가 수기 대비 더 완전(누락 0)하고 재현 가능함을, 후속 수기 채움과의 일치로 실증한 사례.

검증 사례 ② — 자본 건설공사 데이터 소스 한계 범위 밖

자본 건설공사(재료비-열원자재비·외주비-열원공사비·외주비-열원기술용역비)는 수기 취합본에 실적 ~17.3M천원이 있으나 zrfm2에 해당 계정이 존재하지 않는다(별도 시스템 소스 추정). 계획에는 존재(19행·8.48M). v1.0 rev2에서 과목구성 실적반영:false로 지정 — 계획본엔 그대로 유지하되 실적 산출물(양식1·종합표)에서만 제외(사용자 확정). 향후 건설공사 실적 파일을 업로드받아 병합하면 커버 가능. 이 -17.3M이 자본 총계 차이(우리 49.7M vs 참조 66.2M)의 대부분.

개선 여지 (자유 설계 영역)

  • 성능 — 약 14,290건 처리. 그룹 사전분할로 후보 비교량을 축소했으나, 대량 처리 시 캐싱/벡터화 여지.
  • 학습형 재사용 — 사람이 확정한 (전표→사업) 매칭을 다음 해 매칭에 재사용(확신도 부스팅).
  • 확신도 임계값 튜닝 — 저유사(<임계값) 귀속 건을 검토리포트로 노출해 정밀도/재현율 조정.

07 · 예산 표준화 STAGE 3 핵심 설계

같은 지사·정비등급·투자유형·예산과목 조합의 과년도 실적에서 "표준 예산(벤치마크)"을 뽑는다. 1단계 계획 수립의 참고값이자 4단계 예측의 베이스라인.

구성 축 4가지

  • 투자유형 — 8종(LTSA·정기사업·노후설비개체·AX/DX·운영안정성 제고·환경강화·교육강화·보안강화). 기존 키워드+TF-IDF/로지스틱 하이브리드 분류 재사용.
  • 정비등급 — 신규 축. 외부 파일 업로드 마스터(스키마 미정 §11).
  • 지사 — 지사유형 매핑(중대형CHP/소형CHP/DH/본사) 재사용. ※ 2단계에서 구축한 처지사 정규화맵·지사그룹을 그대로 승계 가능.
  • 예산과목 — 계정과목 체계 재사용. ※ 2단계의 예산과목 별칭(연도별 개명) 정규화 승계.

산출물 budget_benchmark.csv: 지사·정비등급·투자유형·예산과목·표준금액·표본수/산출근거연도.

10 · 비기능 요구사항

  • 완전 오프라인 — 사내 분리망. rapidfuzz·pandas·openpyxl·streamlit 모두 로컬. 인터넷 불필요.
  • 데이터 로컬 보관 — 실적/예산/벤치마크는 외부 전송 없음. config/*.json·output/는 gitignore.
  • 성능 — 연 약 14,000건 처리 기준 화면 대기 가능 시간 내 완료(2단계 매칭 실측 수초). 대량 시 캐싱 여지 §11.
  • 개발 스택 — Python 3.14 · pandas 3.0 · openpyxl 3.1 · streamlit 1.58 · rapidfuzz 3.14 · pytest(34 통과). pandas 3.0의 None→NaN 변환에 대비해 전 모듈 pd.isna 가드.
  • 데이터 정합성 — 종합표 총액 = 데이터시트/ERP 총액 회귀 테스트로 고정.

11 · 리스크 · 오픈이슈

  • Open — 정비등급 마스터 스키마·조인 키·갱신 주기 미정(§07,§08).
  • Open — 중장기 예측 팩터(노후화·물가) 값의 출처(사내 통계 vs 수동 입력) 미정.
  • Open — 표본 부족 조합의 벤치마크 계산 정책.
  • 해소 ✓ — 처지사 표기 난립(52종)·예산과목 연도별 개명은 정규화맵/별칭으로 흡수(미매핑 0 달성). 미해소 항목은 검토리포트로 노출해 처지사_별칭.json 보강.
  • Risk — 매칭 확신도 임계값(기본 80%)은 경험값. 계획-실적 사업명 텍스트 괴리가 커서, 사업명 단독 게이트는 부적합(그룹 기반으로 완화). 실데이터로 계속 튜닝.
  • Risk — 로컬 파일 단일 사용자. 동시 편집 시 마지막 저장이 덮어씀.

12 · 용어집

매칭확신도전표↔계획 사업명 rapidfuzz(WRatio) 유사도 0~1. 계획행은 귀속 전표 평균값. 저유사 건은 검토 대상.
