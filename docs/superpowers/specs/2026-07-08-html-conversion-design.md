# 발전플랜트 예산 분석 앱 — HTML/JS 단일 파일 전환 설계

## 배경 및 목적

기존 앱은 Streamlit 기반 Python 앱으로, 실행하려면 Python 설치 + `pip install`(requirements.txt) + `streamlit run app.py`가 필요하다. 이 앱은 사내 폐쇄망(인터넷 차단)에서 사용될 예정이며, 사용자 환경에는 Python이 없거나 pip 설치가 제약될 수 있다(externally-managed-environment 오류 확인됨).

목표: **인터넷 연결도, 별도 설치도 필요 없이 HTML 파일 하나를 더블클릭하는 것만으로 기존 앱과 동일한 기능이 브라우저에서 동작**하도록 전환한다.

## 범위

기존 Streamlit 앱(`app.py`)의 3개 화면 기능을 100% 이전한다.

1. 1단계 · 데이터 업로드 (연도별 현황판, 엑셀 업로드/검증)
2. 2단계 · 투자유형 분류 검토 (분류 결과 검토/확정)
3. 모델 관리 (학습 현황, 재학습, 내보내기/불러오기, 초기화)

## 아키텍처

**단일 `index.html` 파일**에 HTML + CSS + JS + 초기 데이터 + 엑셀 파싱 라이브러리(SheetJS)를 전부 인라인으로 포함한다. 외부 CDN, 외부 스크립트 로드는 일절 사용하지 않는다(폐쇄망 요건).

화면 전환은 실제 페이지 이동이 아니라 탭(사이드바 라디오 대응) 전환으로 구현하며, 기존 Streamlit의 `st.session_state`에 해당하는 상태는 JS 전역 상태 객체 하나로 관리한다.

### 컴포넌트 구성 (파일 내부 논리적 모듈, 전부 하나의 `<script>` 안)

- `state`: 앱의 모든 데이터를 담는 단일 JS 객체 (연도 현황, 연도별 원본 데이터, 분류결과, 학습데이터, 모델 통계)
- `storage`: localStorage read/write, 초기 로드 시 embedded default와 병합
- `validateUpload`: 기존 `validate_upload.py`의 컬럼 위치 기반 검증 로직을 1:1 포팅
- `classify`: 기존 `classify.py`의 키워드 규칙을 1:1 포팅
- `mlClassifier`: 신규 — 문자 n-gram 기반 나이브베이즈 분류기 (아래 "AI 분류기" 절 참조)
- `hybridClassify`: 학습된 모델이 있으면 `mlClassifier`, 없으면 `classify` 사용 (기존 `hybrid_classify.py` 대응)
- `yearStatus`: 5칸 현황판 계산 로직 (기존 `year_status.py` 1:1 포팅)
- `ui`: 3개 탭의 렌더링 및 이벤트 핸들러
- `xlsxParser`: SheetJS를 이용한 업로드 엑셀 파싱

## 데이터 저장 전략

- **최초 실행 시**: 현재 보유한 `year_status.json`, `data_2016.csv`, `classified_2016.csv`, `training_data.csv` 내용을 JS 상수로 파일 안에 내장(embed)하여, 아무 것도 안 해도 10년치 데이터와 학습데이터가 이미 채워진 상태로 시작한다.
- **사용 중**: 신규 업로드/분류 확정/재학습 결과는 매 변경마다 `localStorage`(key: `budget_app_state_v1`)에 JSON으로 자동 저장한다. 브라우저를 껐다 켜도 유지된다.
- **이동/백업**:
  - "전체 백업 내보내기": 현재 `state` 전체를 JSON 파일로 다운로드. "불러오기"로 다른 PC의 브라우저에 그대로 주입 가능.
  - "학습 데이터 내보내기/불러오기": 기존과 동일하게 `text,label` CSV로 내보내기/불러오기(병합 또는 전체교체 모드 유지).
- Python의 `type_classifier.joblib`(sklearn 파이클 모델)은 JS에서 재사용 불가능하므로 이전하지 않는다. 대신 최초 실행 시 내장된 `training_data.csv`로 JS 분류기를 즉시 1회 자동 학습시켜 시작 상태를 맞춘다.

## AI 분류기 (핵심 변경점)

기존: TF-IDF(char n-gram 2~4) + 로지스틱회귀 (scikit-learn, Python 전용)

신규: **문자 n-gram(2~4) 카운트 기반 다항 나이브베이즈**를 순수 JS로 구현.

- 인터페이스는 기존과 동일하게 유지: `predict(text) -> {label, confidence}`
- 학습(`train(examples)`)은 카운트 집계이므로 연산 비용이 낮아, "재학습" 버튼을 누르면 즉시 완료된다.
- 정확도 참고치는 k-fold(가능한 경우 최대 5-fold, 기존과 동일한 최소 fold 계산 로직 포함)로 직접 구현한 교차검증으로 산출한다.
- sklearn과 100% 동일한 정확도는 보장하지 않음을 모델 관리 화면에 동일하게 안내 문구로 유지한다(기존에도 "참고용" 표기).

## 화면별 동작 (기존 로직 1:1 대응)

### 1단계 · 데이터 업로드
- 5칸 현황판: 최근 4개년 개별 + 이전 연도 그룹(펼쳐보기) — `year_status.js` 로직 그대로
- "다음/이전 연도 추가" 버튼
- 엑셀 업로드 시 SheetJS로 파싱 → `validateUpload`로 컬럼 위치(E,G,L,N,O 대응 인덱스) 기반 검증 → 치명적 오류/경고 구분 표시 → "이 결과로 저장하기"로 `state`에 반영 + localStorage 저장

### 2단계 · 투자유형 분류 검토
- 연도 선택 → 해당 연도 데이터에 `hybridClassify` 적용 → 확신도 오름차순 정렬
- 확신도 0.7 미만 항목만 검토 UI(직접 유형 선택) 노출, 나머지는 통계만 표시
- "확신 높은 항목 일괄 승인 + 검토 반영 저장" / "변경사항만 저장" 버튼 — 저장 시 학습데이터에 확정 라벨 누적

### 모델 관리
- 누적 학습데이터 건수/유형별 분포, 마지막 학습 시각/정확도 표시
- "지금 재학습하기" (최소 샘플 20건, 최소 유형 2개 조건 동일)
- 학습데이터 내보내기(CSV)/불러오기(병합·전체교체)
- "모델만 초기화"(학습데이터 보존, 모델 통계만 삭제) / "전체 초기화"(확인 체크 필요)

## 에러 처리

- 엑셀 파싱 실패, 필수 컬럼 없음 등은 화면에 즉시 에러 메시지로 표시 (기존 `st.error` 대응)
- 검증 오류/경고는 기존과 동일하게 표(행 번호/구분/유형/상세) 형태로 표시
- localStorage 용량 초과 등 저장 실패 시 사용자에게 알리고 "백업 내보내기"를 권장하는 안내 표시

## 테스트 방법

빌드/테스트 프레임워크가 없는 단일 HTML 파일이므로:

- **자체 점검(자동)**: URL에 `?selftest=1`을 붙여 열면, 페이지 로드시 핵심 로직(검증 규칙 케이스별 판정, 나이브베이즈 분류기 학습→예측 정확도, 5칸 현황판 계산 로직)에 대한 assert 기반 점검을 실행하고 결과를 콘솔 및 화면 상단 배지로 표시한다.
- **수동 시나리오 테스트**: 브라우저에서 직접 (1)신규 연도 추가→업로드→검증 오류 확인, (2)분류 검토→일괄승인 저장→학습데이터 누적 확인, (3)재학습→정확도 표시 확인, (4)새로고침 후 데이터 유지 확인, (5)전체 백업 내보내기→다른 브라우저 프로필에서 불러오기 확인.
