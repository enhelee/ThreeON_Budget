발전플랜트 유지보수 예산 분석·예측 프로그램

01프로젝트 제목

발전플랜트 유지보수 예산 분석·예측 프로그램

실적을 자동 분류·매칭하고 계획 대비 실적과 10개년 예측을 만드는 사내 도구

02프로젝트 소개

무엇을 만드나 — 발전플랜트 지사별 유지보수 예산의 ERP 실적 전표를 자동으로 사업·투자유형에 분류·매칭하고, 계획 대비 실적 리포트와 향후 10개년 예산 예측까지 만드는 웹 프로그램.
누구를 위해 — 본사 예산 담당자(실적 업로드·검토·리포트 배포), 지사 담당자(예산계획 업로드), 관리자(리포트·예측 소비).
왜 (어떤 문제를 해결) — 매년 수천~수만 건의 전표를 수기로 분류하던 작업을 자동화하고, 확신도가 낮은 건만 사람이 검토하게 해 시간을 크게 줄인다. 수기 취합이 비워두던 "지사 귀속" 실적도 전표 매칭으로 자동 정량화한다.

04기술 스택

프론트엔드 — Streamlit (Python 기반 웹 UI, 사이드바 메뉴 5단계 + 설정)
백엔드 — Python 3.13 · pandas(데이터 처리) · openpyxl(엑셀) · rapidfuzz(사업명 유사도 매칭) · scikit-learn(투자유형 분류 모델)
데이터베이스 / 기타 — 별도 DB 없음. 로컬 CSV·Excel 파일 기반. 사내 분리망 완전 오프라인 동작(외부 전송 없음).
사용 도구·서비스 — Claude Code(개발) · Git/GitHub(버전관리) · pytest(테스트 41개)

05진행 상황

전체 단계: 기획 – 화면설계 – 개발 – 테스트 – 배포

현재 위치: 개발 본인 담당 화면 대부분 완료 / 핵심 모듈은 동료와 분담 개발 중

완료된 것

  • 전체 메뉴 구조 확정(예산 계획 수립 → 실적 집계 → 실적 분석 → 표준화 → 중장기 예측)
  • 실적 업로드·검증(합계행·역분개·인지세 등 자동 정제), 예산 계획 업로드
  • 사업 매칭(임시 견본, 소액 자동분류·일괄 매칭 포함), 투자유형 분류(키워드+학습 모델)
  • 계획 대비 실적·양식 엑셀 채움, 집계 대시보드·맞춤 리포트, 10개년 예측
  • 지사/부서 코드 매핑 개선 → 실데이터에서 미집계 1,133건 → 15건으로 감소
  • 실데이터 유출 방지(.gitignore), 단위 테스트 41개, PRD·연동규격서 문서화

진행 중인 것

  • 동료의 핵심 매칭 모듈(budget_app)과 본인 프로그램의 연동 규격 맞추기
  • 예산 표준화(벤치마크)·중장기 예측(팩터) 설계

06현재 문제

막힌 점 (기술·기능)

  • 같은 기능(전표–사업 매칭)을 두 개의 다른 구현(본인 개발중/ vs 동료 budget_app)이 병렬로 만들어져 있어, 이 둘을 어떻게 합칠지가 관건.
  • "투자유형 분류 검토"를 누가 만드는지 담당이 서로 어긋나 있음(본인은 동료 담당으로 알지만 동료 PRD엔 빠져있음).
  • 계획과 실적의 사업명 표기 차이가 커서 사업명만으로는 매칭 정밀도가 낮음(그룹 기반 보완 중).
  • 사내망 인증 문제로 로컬에서 GitHub push가 막힘(인증서/토큰 이슈).

강사 / 수업에 요청

  • 두 사람이 나눠 만든 코드를 파일(CSV) 규격만으로 안전하게 연동/병합하는 방법이 맞는지 검토.
  • Streamlit 앱을 사내망 사용자들에게 배포하는 현실적인 방법(실행/공유).
  • 텍스트 유사도 매칭의 정밀도를 높이는 접근(표기 차이가 큰 한글 데이터).

07다음 계획

  • 동료와 연동 규격서 확정 — 특히 투자유형 분류 담당·출력 파일 합의.
  • budget_app 통합 방식 결정(별도 앱 유지 vs 하나로 병합) 후 본인 화면과 연결.
  • 예산 표준화 착수 — 정비등급 마스터 파일 스키마·조인 키 확정, 조합별 기준값(벤치마크) 산출.
  • 중장기 예측 설계 — 노후화·물가상승 등 예측 팩터의 값 출처(사내 통계 vs 수동 입력) 결정.
