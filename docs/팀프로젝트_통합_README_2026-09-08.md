## 1. 두 앱, 하나의 파이프라인

```
 ① 예산 계획 수립 ─ ② 실적 집계·사업 매칭·검토·학습 ─▶ [결과 JSON] ─▶ ③ 예산 표준화 ─ ④ 중장기 예산(26~35년)
 └───────── budget_app (FastAPI :8010) ─────────┘            └── 예산예측프로그램_팀공유_v2 (Streamlit :8501) ──┘
            사용자 파트 · 검증된 매칭 엔진                              동료 파트 · 3·4단계 + 대시보드·리포트·투자유형 분류
```

| 앱 | 폴더 | 담당 | 실행 | 테스트 |
|---|---|---|---|---|
| **예산·실적 분석(budget_app)** | `budget_app/` | 계획본 생성 · zrfm2 실적 매칭 · 검토/수정/학습 · 통계 · **팀 연계 내보내기** | `budget_app/분석프로그램_실행.bat` → <http://localhost:8010> | `py -m pytest -q` → **77 passed** |
| **예산예측프로그램(팀공유 v2)** | `예산예측프로그램_팀공유_v2/` | 실적 업로드·투자유형 분류·대시보드·맞춤 리포트 · **예산 표준화 · 중장기 예산 26~35년** · 사업 실적 연결 | `예산예측프로그램_v2_실행(로컬).bat` → <http://127.0.0.1:8501> | 폴더에서 `py -m pytest tests/ -q` → **183 passed** |

- v2 원본 `실행_Windows.bat`은 **Python 3.12 전용**(`py -3.12 -m venv`)이라 이 PC(3.14)에서는 루트의 `예산예측프로그램_v2_실행(로컬).bat`을 쓴다. 3.14에서 183건 통과했으므로 기능 차이는 없다.
- 두 앱은 코드를 합치지 않고 **파일 계약**으로만 이어진다(사내 분리망·오프라인 전제 동일).

## 2. 연결 절차 — 매칭 결과를 표준화·예측에 넘기기

1. **budget_app**에서 연도 선택 → 계획본·zrfm2 업로드 → `분석 실행` → 상세 화면에서 재배정·수정 → `분석 반영` → (선택) `AI 학습`.
2. 「4 통계·내보내기」 맨 위 **팀 연계 패널 → `결과 JSON (사업 실적 연결)`** 클릭 → `팀연계_{연도}_사업실적연결.json` 다운로드(첫 생성 20초 안팎).
   - 같은 패널의 `matched 통합 CSV`·`budget CSV`·`data CSV`는 [연동규격_INTERFACE.md](연동규격_INTERFACE.md) 계약 파일(연도 단일, 원 단위).
3. **v2 앱** 메뉴 「예산 실적 집계 → 사업 실적 연결」 → 2번 JSON 업로드 → 원천순액·연결금액·제외·미배정 확인(우리 JSON은 **미배정 0**) → `배정분을 표준화·중장기 예산에 연결`.
4. 「예산 표준화」·「중장기 예산 (26-35년)」에서 **「연결한 사업 실적」** 선택 → 정비등급 이력·일정·본사배분·팩터 입력 후 계산·엑셀 내보내기.

현재 상태: **2023·2025년 JSON이 v2에 이미 연결됨**(`예산예측프로그램_팀공유_v2/checkpoint_data/`, 사업행 2,531개 · 2,762.49억원). 재분석 후 다시 내보내 올리면 새 버전이 활성화되고 이전 버전은 보관된다.

주의: v2의 「연결한 사업 실적」은 **배정분만** 표준화 입력으로 쓴다. budget_app에서 과목·지사를 선택 해제한 상태로 내보내면 그 금액은 '제외'로 표시되고 입력에서 빠지므로, **내보내기 전에는 구성을 전체 선택**으로 두는 것을 권장한다.

## 4-1. 배포·보안·학습 관리 (2026-09-09 추가, rev15)
- **패키지**: `2026-09-09-team-package-v0/` — GitHub 업로드용 최종본(`budget_app/ forecast_app/ docs/ deploy/ matching_tool_src/`, 루트 `Dockerfile`·`render.yaml`·`.env.example`·실행기). `업로드용_…_팀통합/`(9/8)은 이 폴더로 대체.
- **배포 경로**: 지금 Render(Docker) + Supabase(PostgreSQL) + GitHub Pages(소개) → 최종 사내 서버 `docker compose`. Vercel은 정적 소개 페이지에만 적합. → [배포가이드.md](배포가이드.md)
- **접근 통제**: 팀 공용 비밀번호(`APP_PASSWORD`) + 로그인 시 **작업자 이름** → 모든 변경이 `audit_log`에 기록(설정 탭 「변경 이력」). `/forecast`는 Caddy 기본인증. 비밀은 `.env`/Render 환경변수에만. → [보안설계.md](보안설계.md)
- **DB**: 기본 SQLite, `.env`의 `DATABASE_URL`로 PostgreSQL 전환(`src/budget/dbcore.py`). 최초 PG 접속은 `py scripts/db_check.py`로 확인.
- **모델·학습데이터**: v2 분류기 3종을 budget_app DB 레지스트리(버전·BLOB·스냅샷)로 관리, 확정 우선·수동 재학습·롤백. v2 폴더와는 `py scripts/v2_model_sync.py --push/--pull`. → [학습데이터_모델_관리.md](학습데이터_모델_관리.md)
- **소개 사이트**: `docs/index.html`(패키지) = 로컬 `site/index.html`. 팀원 안내는 [팀원_실행가이드.md](팀원_실행가이드.md).
